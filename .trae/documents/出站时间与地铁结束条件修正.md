# 出站时间与地铁结束条件修正

## 摘要

两处不符合数据可信度顺序的问题：

1. **出站不能由下车推算**。出站来自刷卡通知（`岭南通·羊城通 08:06 刷卡完成，交易金额：x元`），准确且无需人工；下车打卡容易遗漏。方向只能是「下车缺失时用出站倒推」，不能反向。
2. **地铁行程必须以出站为结束条件**。终点站下车打卡（或到站判定）只代表离开车厢，人可能还在站台/通道；当前实现会直接结束整趟行程。

已确认的结束信号：**刷卡出站 + 基站离开地下**（`MetroGate.Edge.EXIT`）。到家/到公司不再作为地铁行程的自动结束依据；公交最后一段没有出站概念，保持现有到站结束逻辑。

## 改动方案

### 1. NodeLog：出站只记实测，不推算

文件：`app/src/main/java/com/busnotice/commute/NodeLog.kt`

* 删除 [L187-L190](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/NodeLog.kt#L187-L190) 整个 `if (!aborted && metro && exit == null)` 块。
* 删除 `Anchors` 的 `exitWalkSec` 字段（L35）。
* `resolve()` 里 ARRIVE 的 anchor 保持「地铁看 EXIT、非地铁看 ALIGHT」：地铁没出站就推不出到达，符合「没出站不算到」。
* 更新类注释与 `resolve` 注释：出站只来自刷卡（TAP）或基站判定（AUTO），任何情况下都不用下车时间生成。

### 2. Learn / settleNodes：移除出站步行的补算消费

文件：`app/src/main/java/com/busnotice/commute/Learn.kt`、`CommuteService.kt`

* 删除 `Learn.exitWalkSec()`（L238-L239），它只被结算使用。
* `settleNodes()`（L629-L642）删除 `exitWalkSec = ...` 参数。
* `Learn.Metric.EXIT_WALK` 与 `learnNodes()` 里的 `recordNode(EXIT_WALK, ...)`（L676）**保留**：它统计的是「出站实测 − 下车（实测或出站倒推）」的真实差值，仍有数据价值；只是不再参与补算。

### 3. CommuteService：地铁最后一段的下车不再结束行程

文件：`app/src/main/java/com/busnotice/commute/CommuteService.kt`

统一判定辅助：

```kotlin
/** 最后一段是地铁、且还没出站：下车/到站都不能结束行程 */
private fun metroStillInside(): Boolean {
    val last = trip.legs.lastIndex
    if (trip.legs.getOrNull(last)?.isMetroOnly() != true) return false
    return NodeLog.flow.value.none { it.kind == NodeLog.Kind.EXIT && it.leg == last }
}
```

（放在 `ackAlight()` 附近，使用前加 `::trip.isInitialized` 判断。）

#### 3.1 `ackAlight()`（L543-L567）

最后一段分支改为：


#### 3.4 `placeFix()` 到家/公司（L1770-L1778）

在 H3 兜底判断内先挡一道：


#### 3.5 保持不变的结束路径

* 刷卡 `EXIT`（L2218-L2236）：最后一段 `EXIT(TAP)` → `endTrip`；中间段换乘。
* 用户点「结束行程」：`userFinish()` → `finish()`，`aborted = true`，不补未来节点。
* 截止时间到：`runLoop()` 退出后 `finish()`。
* 公交最后一段：`ackAlight`、`rideTick` 到站、`placeFix` 都按原逻辑结束。

## 决策与假设

* **出站唯一来源**：刷卡通知（`TAP`）或离开地铁基站的自动判定（`AUTO`）。人工长按补录仍允许，标记为 `BACKFILL`，不算推算。
* **「我已下车」在最后一段地铁只记下车**，通知与胶囊继续保留到出站；用户想立刻收尾可以点「结束行程」。
* **基站出地视为出站**（用户已确认），用于兜底刷卡通知丢失。
* **到家/到公司不再结束未出站的地铁行程**（用户已确认，只认刷卡 + 基站）。行程会继续到截止时间或用户手动结束。
* **公交最后一段**没有出站节点，维持现有到站结束逻辑。
* `alightEstimateSec`（编辑页「终点下车比出站提前」）只用于从出站倒推下车，文案同步改为这个含义。

## 验证

1. CI：推送后由 GitHub Actions 跑 `assembleDebug` + `testDebugUnitTest`，确认 NodeLog 新用例通过。
2. 真机 · 正常出站：终点站下车打卡后行程不结束、胶囊仍在；刷卡出站后立即结束，最近行程里「出站」不带「≈」。
3. 真机 · 忘记下车打卡：出站后下车时间 = 出站 − `alightEstimateSec`，显示「≈」；出站为实测时间，无「≈」。
4. 真机 · 刷卡出站通知丢失：离开地下基站后自动结束，出站显示自动判定时间。
5. 真机 · 下车后直接回家：行程不因「到家」结束；刷卡出站或手动结束后正常结算。
6. 真机 · 公交最后一段：到站仍自动结束，行为不变。
