# 统一每段乘车时长：单一解析入口

## Summary

把 `Learn.rideMin`（实测中位数）、`Leg.rideMin`（手填，默认值来自地铁站数估算）、`metroRideSec`（地铁按站数估算）三者的优先级判断收口到一个唯一入口 `Learn.ride(...)`，返回一个 `Ride(minutes, source)`。应用里所有“这段坐多久”的显示与计算（实时到站、截止时间、出发建议、编辑页步进器与说明）都只读这一个结果，不再各自判断三个值。

优先级：**实测中位数 > 手填值 > 地铁按站数估算 > rideMin 兜底（默认 10）**。

编辑页仍允许修改时长；若该段已有实测样本，提交前弹确认框，确认后**清空该段实测记录**（之后重新统计），再把新值写为手填值。

## Proposed Changes

### 1. Learn.kt：新增唯一解析入口与清空样本

- 新增：

```kotlin
data class Ride(val minutes: Int, val source: Source) {
    enum class Source { LEARNED, MANUAL, ESTIMATE, DEFAULT }
}

/** 纯函数，便于单测：实测（可按 joinScale 缩放）> 手填 > 地铁站数估算 > 兜底 */
fun resolve(learnedMin: Int?, leg: Leg, metroSec: Int?, learnScale: Double = 1.0): Ride

fun ride(ctx: Context, trip: Trip, legIdx: Int, metroSec: Int? = null, learnScale: Double = 1.0): Ride =
    resolve(rideMin(ctx, trip.id, legIdx), trip.legs[legIdx], metroSec, learnScale)

/** 清空某段实测乘车时长，之后重新累计 */
fun resetRide(ctx: Context, tripId: String, legIdx: Int) {
    ctx.getSharedPreferences(RIDE, Context.MODE_PRIVATE).edit().remove("$tripId#$legIdx").apply()
}
```

- `resolve` 规则：
  1. `learnedMin != null` → `Ride((learnedMin * learnScale).toInt().coerceAtLeast(1), LEARNED)`；
  2. `leg.rideMinManual` → `Ride(leg.rideMin, MANUAL)`；
  3. `metroSec != null` → `Ride(((metroSec + 59) / 60).coerceIn(1, 120), ESTIMATE)`；
  4. 否则 `Ride(leg.rideMin, DEFAULT)`。
- 更新 `rideMin` 的注释（不再写“用行程里手填的”）。

### 2. Model.kt：移除分散的快捷判断

- 删除 `Leg.rideSec(...)`（由 `Learn.resolve` 取代），保留 `rideMinManual` 字段及其 JSON 序列化（只作为“是否手填”的元数据，不再参与多处判断）。

### 3. CommuteService.kt：只读统一结果

### 4. DepartAdvisor.kt：删除自建优先级

## Assumptions & Decisions

- 按用户确认：采用**运行时统一解析**，不把结果回写/持久化到 `Leg.rideMin`；`rideMin` 仍只保存“手填值（默认来自站数估算）”。
- 实测严格覆盖手填：只要该段攒够 3 次实测，显示和计算都取实测中位数；用户要改就以“清空实测样本”为代价。
- 清空只针对该 `tripId + 段序号` 的乘车样本（`learn_ride2`），不影响公交速度、地铁偏差等其他学习数据。
- 编辑页的站数估算仍通过 `MetroRoutes.get` 获取；运行时优先使用服务预取的 `metroRideSec`（该值本身优先于离线兜底）。
- 选择器添加线路时仍按站数把估算写入 `rideMin` 并视为手填默认值，行为不变。
