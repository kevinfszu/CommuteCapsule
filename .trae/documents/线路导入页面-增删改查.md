# 「数据源」改为「线路导入」（增删改查）

## Summary

1. 把「数据源」页面改名为「线路导入」，入口仍在设置页。
2. 页面改成典型增删改查：
   - **查**：只列出已导入的线路（正反方向归并为一条），点进去看详情；
   - **增**：导入 JSON 文件、用高德查询并生成（两种方式都保留）；
   - **改**：详情页可修改单站用时、以及每个方向的始发站首末班；
   - **删**：详情页删除单条线路（两个方向一起删），列表页保留「清空全部线路」。
3. JSON 导入行为改为**与已有线路合并、同名覆盖**；删除最后一条线路后恢复扩展源 / 内置演示数据。

## Proposed Changes

### 1. 数据层：支持合并导入、单条修改、单条删除

#### 1.1 `JsonTransit.kt`：新增纯 JSON 编辑函数（不依赖 Android，便于单测）

新增以下函数：

```kotlin
/** 合并：incoming 里出现的同名线路，先从 existing 移除，再追加 incoming；existing 为空/不可解析直接返回 incoming */
fun merge(existing: String?, incoming: String): String

/** 删除指定显示名的全部方向记录；删完没有线路返回 null；结果必须能通过 parse 校验 */
fun deleteLine(text: String, name: String): String?

/** 修改同名全部方向记录的 hopSec；并按方向 id 覆盖始发站 first/last；返回新 JSON 文本 */
fun updateLineParams(
    text: String,
    name: String,
    hopSec: Int,
    clocks: Map<String, Pair<Int, Int>>,   // key = line.id，value = (firstMin, lastMin)
): String
```

实现要点：

- `merge`：把 [AmapData.merge](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/AmapData.kt#L162-L184) 的实现原样搬到 `JsonTransit`；保留 `region` / `meta` / `lines` 结构，末尾用 `JsonTransit.parse` 校验。
- `deleteLine`：用 `JSONObject` 读原文，过滤 `lines` 数组；剩余为空返回 `null`，否则 `toString(2)` 后 `parse` 校验再返回。
- `updateLineParams`：遍历 `lines`，`name` 匹配的记录统一写 `hopSec = hopSec.coerceIn(20, 900)`；若该记录 `id` 在 `clocks` 中，写 `first`/`last`（`HH:mm`，分钟数按 1440 取模）。保留 `service`、`color`、`reverseId` 等未编辑字段；结果 `parse` 校验。
- 全部函数遇到非法 JSON 直接抛 `IllegalArgumentException`，由界面捕获并 Toast。

同时把 `AmapData.merge` 删除，调用点统一改到 `JsonTransit.merge`（[AmapImportScreen.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/AmapImportScreen.kt#L137-L145)、[AmapDataTest.kt](file:///e:/001-Program/CommuteCapsule/app/src/test/java/com/busnotice/commute/AmapDataTest.kt#L187-L193)）。

#### 1.2 `ImportedJsonSource.kt`：暴露线路并落盘

- 新增 `val lines: List<JsonTransit.Line> get() = doc?.lines.orEmpty()`，供列表和详情页读取。
- 新增 `fun importMerged(ctx: Context, text: String): JsonTransit.Doc`：
  读取 `rawText(ctx)` → `JsonTransit.merge(existing, text)` → 复用现有 `import(ctx, merged)` 的「先解析校验、临时文件再重命名」流程。
- 新增 `fun updateLine(ctx, name, hopSec, clocks): JsonTransit.Doc`：
  `rawText` → `JsonTransit.updateLineParams` → `import(ctx, updated)`；没有原始文件时抛 `IllegalStateException("尚未导入线路")`。
- 新增 `fun deleteLine(ctx, name): Boolean`：
  `rawText` → `JsonTransit.deleteLine`；返回 `null` 时调用 `clear(ctx)` 并返回 `false`；否则 `import(ctx, remaining)` 并返回 `true`。
- `import()`、`clear()`、`rawText()` 保持不变。

#### 1.3 `Transit.kt`：门面与缓存刷新

- `importJson(ctx, text)` 改为调用 `ImportedJsonSource.importMerged`，实现「合并覆盖同名」；其余缓存清理逻辑（`clearColorCache`、`MetroRoutes.clear`、`region`）保持不变。
- 新增：

```kotlin
/** 修改已导入线路的运行参数；失败抛异常 */
fun updateImportedLine(ctx: Context, name: String, hopSec: Int, clocks: Map<String, Pair<Int, Int>>): ImportSummary

/** 删除一条线路（两个方向）；删空后恢复扩展源/演示城市 */
fun deleteImportedLine(ctx: Context, name: String)
```

实现：

- `updateImportedLine`：`synchronized` 内调用 `ImportedJsonSource.updateLine`，`static = ImportedJsonSource`，清 `colorCache` 与 `MetroRoutes`，返回 `ImportSummary(doc.lineCount, doc.stationCount)`。
- `deleteImportedLine`：`synchronized` 内调用 `ImportedJsonSource.deleteLine`；返回 `false`（已删空）时走现有 `clearImported` 逻辑恢复扩展源/演示城市，返回 `true` 时清缓存并保持 `static = ImportedJsonSource`。

## Assumptions & Decisions

- 编辑范围按用户确认：**只改单站用时 + 各方向始发站首末班**；线路名、站点、线路色、区间发车间隔不可在本页修改。
- 列表只展示**已导入**线路；内置演示与 `src/extra` 扩展源线路不出现，未导入时显示空状态。
- 顶部按用户确认**精简保留**：一行当前数据源 + 数据说明小字，去掉实时到站行和独立说明卡。
- JSON 导入按用户确认**合并覆盖同名**；高德生成保持合并行为。
- 删除最后一条线路按用户确认**恢复内置演示/扩展源**。
- 线路以显示名归并，两个方向视为同一条线路；删除/修改按名称作用于全部方向记录。
- 不引入通用导航栈，继续使用单 `Screen` 状态机；详情页返回固定回「线路导入」。
- 不做未保存修改拦截，保持页面轻量。
