# 修复：行程中「到站打卡」列表从沙村开始、看不到车陂

## 结论（已用手机上的行程数据证实）

线路与方向没有问题。本次行程第 1 段是 13 号线，**开往 天河公园**，缓存的路由站序为：

```
白江(0) → 沙村(1) → 南岗(2) → 夏园(3) → 南海神庙(4) → 双岗(5) → 裕丰围(6) → 鱼珠(7) → 天河珠村(8) → 车陂(9) → 棠下(10) → 天河公园(11)
```

车陂就是天河珠村的下一站（8 → 9），方向判断正确，不存在「补打更早站点」这种事——上一版计划里这句话是我搞错了。

真正的原因是**弹窗用「预测位置」当作列表中心，而这个值在到站提醒触发后变成 null**：

1. 07:50 你在「天河珠村」打卡，记录正确（`marks` 落库、`learn_stops_v1` 里 13 号线的 190/198 秒样本就是由 8 号站的打卡推算出来的，「上次打卡：天河珠村 07:50」也在轨迹里）。
2. 07:53:37 服务触发了到站提醒（轨迹 `arrive_alert stage=T2 left=2`）。
3. 触发提醒后 `rideTick` 里的 `stopUi` 变为 `null`，发布的快照 `stopsPassed = null`（[CommuteService.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/CommuteService.kt#L1734-L1748)）。
4. 07:53:44 打开「到站打卡」，弹窗用 `here = (s.stopsPassed ?: 0)`，null 变成 **0**：
   - `from = (0-5).coerceAtLeast(1)` = **1 → 沙村**
   - `to = (0+5).coerceAtMost(10)` = **5 → 双岗**
   - 列表只有 沙村/南岗/夏园/南海神庙/双岗 5 行，车陂（9 号）根本不在窗口里；5 行也没超出高度，所以看起来「不能滚动」。

即：[LiveBoard.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/LiveBoard.kt#L353-L366) 的 ±5 窗口完全依赖一个可能为 null/stale 的预测值，而已经确认的打卡记录（stopMarks）根本没参与计算。

## 改动（只动选站弹窗）

文件：`app/src/main/java/com/busnotice/commute/ui/LiveBoard.kt`

1. **不再用预测值切窗口，直接列出本段全部可打卡站**（上车站、下车站除外）：
   ```kotlin
   val rows = (1 until stopNames.size).toList()
   ```
2. **「当前」高亮与初始滚动位置以打卡记录优先**：
   ```kotlin
   val markIdx = stopMarks.maxOfOrNull { it.idx }
   val here = listOfNotNull(s.stopsPassed, markIdx).maxOrNull()   // 可能为 null
   ```
   - 有打卡记录时一定落在打卡站上，不再出现「刚打完天河珠村却从沙村开始」；
   - 两个值都没有时不高亮「当前」，也不猜位置。
3. **列表高度按行数显式算，保证能滚**：
   ```kotlin
   val rowHeight = 46.dp
   val listHeight = rowHeight * rows.size.coerceAtMost(8)
   val listState = rememberLazyListState(
       initialFirstVisibleItemIndex = ((here ?: 1) - 1 - 2).coerceIn(0, (rows.size - 1).coerceAtLeast(0))
   )
   LazyColumn(Modifier.padding(top = 8.dp).fillMaxWidth().height(listHeight), state = listState) {
       items(rows, key = { it }) { i -> ... }
   }
   ```
   站点下标 `i` 在列表中的位置是 `i - 1`，所以初始滚动到 `here - 3`。
4. 说明文字加一行 `共 N 个可打卡站，可上下滑动`。
5. 不改 `markStop` 的「不允许回头」逻辑——本次场景是往前打卡（8 → 9），无需改动其他行为。

新增 import：`androidx.compose.foundation.lazy.rememberLazyListState`。
