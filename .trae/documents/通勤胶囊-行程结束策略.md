# 通勤胶囊：行程结束策略改为「手动结束 / 到达目的地自动结束」

## 一、目标

* 出站或下车**不再结束行程**，只记录到站节点。
* 行程只在两种情况下结束：
  1. 用户手动点「已到目的地 / 结束并记录」；
  2. 到家、公司或设定目的地 150 米内驻留满 3 分钟后自动结束。
* **计划结束时间完全不参与结束判断**：出站前无论到点多久、续期多少次，行程都不会因时间自动结束；它只用于看板上的预计时刻与提示。
* 出站后若 30 分钟仍未结束，兜底自动结束；**兜底结束的时刻不进入算法学习**，但本次行程的其它数据照常学习。
* 出站到目的地这段步行保留在首页看板上可见，直到结束。

## 二、现状分析

结束入口分散，行为不一致：

| 位置                            | 当前行为                                                   |
| ----------------------------- | ------------------------------------------------------ |
| `ackAlight()` 末段公交（约 756 行）   | `arrived = true` → `endTrip("ack")` 立即结算               |
| `rideTick()` 末段公交到站（约 1954 行） | 打 ALIGHT → `arrived = true` → `endTrip()` 立即结算         |
| 地铁刷卡/基站出站（约 2714 行）           | 打 EXIT → `arrived = true` → `endTrip("tap_exit")` 立即结算 |
| 地铁基站出站（约 2990 行附近）            | 不结束，等目的地驻留（唯一符合新要求的路径）                                 |
| `placeFix()`（约 2214–2237 行）   | 目的地/家/公司驻留 3 分钟 → 打 ARRIVE → `finish()`                |
| `endTrip()`（约 2265 行）         | 结算并进入 `tail` 静默步行模式，最长 25 分钟                           |
| 主循环截止时间                       | `finish()`，乘车途中到点也会结束（本次要修掉的问题）                        |

学习侧：`settleNodes` → `LearnRebuild` 的全程时长与末段步行只在存在 ARRIVE 节点时写入，因此「不学兜底结束时刻」可以通过**不打 ARRIVE 节点**直接实现。

现有可用机制：`stampCurrentNode()` 已支持「最后一段地铁已出站 → 现在到达」并调用 `userFinish()`，可作为手动到达的复用入口。

## 三、改动方案

### 3.1 `CommuteService.kt`

**新增状态（替代 `tail`）**

```kotlin
private var postExit = false        // 已出站/已下车，正在前往目的地
private var postExitAt = 0L
private val POST_EXIT_MS = 30 * 60_000L
```

**新增 `beginPostExit(at: Long, reason: String)`**

* `if (postExit || finishing) return`
* `postExit = true; postExitAt = at`
* `resetAlightGuard()`、`AlarmBuzzer.stop()`、`stepSensor(false)`
* `deadlineAt = at + POST_EXIT_MS`（出站时刻 + 30 分钟，不再沿用原计划截止），同时设置 `WakeAlarm` 并 `saveRun(deadlineAt)`
* `setPower(Power.LOW)`，`holdCpu(true)` 不变
* `LiveNotifier.replace(quiet("${trip.name} 已到站", "正在前往目的地，到家/公司后自动结束"))`
* `TraceLog.event("post_exit", "reason" to reason, "leg" to legIdx)`

**替换四处结束调用**

1. `ackAlight()` 末段公交：`arrived = true; endTrip("ack")` → `beginPostExit(now, "ack")`
2. `rideTick()` 末段公交到站：`stampNode(ALIGHT...)` 后 `beginPostExit(now, "ride_...")`，不再设置 `arrived`
3. `applyTransit(EXIT)` 末段地铁：打 EXIT、`markAlight` 后 `beginPostExit(at, "tap_exit")`
4. 基站出站路径：统一改为 `beginPostExit(exitAt, "cell_exit")`（原先只是继续跑，现显式进入该阶段，便于看板与恢复）

`metroStillInside()` 的保护保持不变：末段地铁未出站时，任何路径都不得进入 `beginPostExit`。

**主循环彻底移除时间结束条件**

`runLoop()` 改为：循环只在 `finish()` 时退出，出站前没有任何时间判断。

```kotlin
private suspend fun runLoop(deadline: Long) {
    deadlineAt = deadline
    while (scope.isActive && !finishing) {
        // 只有出站后的兜底超时会结束；出站前到点也不结束
        if (postExit && System.currentTimeMillis() >= deadlineAt) { finish(); return }
        val wait = try { tick() } catch (e: Exception) { Log.w(TAG, "刷新失败", e); 20_000L }
        delay(wait)
        // 原有 freeze 诊断保持不变
    }
}
```

* 未出站：`deadlineAt` 只用于看板预计时刻，不影响循环；`WakeAlarm` 不再设置「到点结束」的闹钟。
* 已出站（`postExit`）：`deadlineAt = 出站时刻 + 30 分钟`，到点即兜底结束，走下面的超时结算规则。
* `kick()` 去掉 `deadlineAt <= now` 的提前返回（约 2632 行），只保留 `finishing` 判断，避免截止已过时刷新被拒。

`tick()` 开头增加：

```kotlin
if (postExit) return postExitTick(System.currentTimeMillis())
```

`postExitTick(now)`：

* 发布 `LiveSnapshot(..., riding = false, postExit = true, postExitAt = postExitAt, autoEndAt = deadlineAt)`
* headline「已到站」，detail「前往目的地，到达后自动结束」
* 返回 `30_000L`，不重新开启高频定位；到站判断仍由 `placeFix` 在定位回调里完成

**目的地自动结束**

`placeFix()` 的到站分支：

* 去掉 `!tail` 条件，允许 `postExit` 状态下判定；
* 命中后 `arrived = true`；`stampNode(ARRIVE, 0, loc.time, Src.AUTO)`；`placeVotes()`；`finish()`。

**手动结束**

`userFinish()`：

* 若 `!arrived && boardedAt > 0`：先 `stampNode(ARRIVE, 0, now, Src.MANUAL)` 并 `arrived = true`，再 `finish()`。
* 语义：手动结束代表真实到达，其时刻可参与学习。

**兜底超时结束**

`finish()` 中：

* `settleNodes(aborted = !arrived && !postExit)`；`postExit` 超时不再作废整条记录。
* 超时路径不调用 `stampNode(ARRIVE)`，全程序列/末段步行自然不写入学习，其余节点照常学习。
* 删除 `if (!tail) placeVotes()` 的 tail 判断，改为 `placeVotes()`。

**删除 tail 机制**

* 删除字段 `tail / tailStart / tailFixes / TAIL_MS / DWELL_MS / DWELL_R`、`endTrip()`、`tailTick()` 及 `tick()` 中 `if (tail) return tailTick(...)`。
* 清理引用：`runningId()` 的 `!tail`、`finish()` 的 tail 文案与 `TraceLog.tail_end`、`ackAlight()` 的 `if (!tail) saveRun(...)`（改为无条件）、`stampCurrentNode()` 的 `tail ||` 条件（改为 `postExit ||`）、`onBoarded` 等处的 `tail` 判断。
* `hog` 相关 `repeat` 清理后全项目 `grep tail` 应为 0 处（除历史注释）。

**恢复**

* `saveRun()` 增加 `.putBoolean("postExit", postExit).putLong("postExitAt", postExitAt)`。
* `restoreRun()` 读取两者；`postExit = true` 时确保 `deadlineAt >= postExitAt + POST_EXIT_MS`。`sv` 仍为 2，旧数据缺省 false。
* 截止时间已过的未结束行程不再直接丢弃：`postExit` 时按出站 + 30 分钟结算；未出站时一律恢复继续记录（`deadlineAt` 仅用于展示，不再作为有效性门槛）。陈旧数据清理保持现有逻辑判断，不由截止时间触发。
* 恢复后首帧由 `postExitTick` 负责，看板不闪回「等车」。

**快照字段**

`LiveSnapshot` 增加：

```kotlin
val postExit: Boolean = false,
val postExitAt: Long = 0L,
val autoEndAt: Long = 0L,
```

`toJson/fromJson` 同步；`DemoPlayer` 使用默认值即可。

### 3.2 `ui/LiveBoard.kt`

* 顶部：`s.postExit` 时显示「步行」线路牌（`Fuse.Yellow`），标题「已到站 · 前往 \${trip?.destName ?: "目的地"}」，右侧保留行程名与分段条。
* 主文案：`s.postExit` → headline「已到站」，detail「到达家/公司后自动结束 · 最晚 HH:mm」。
* 操作区：`s.postExit` 时隐藏「到站打卡 / 我知道了 / 我已下车 / 确认上车」，只显示一个主按钮「已到目的地」，点击调用 `CommuteService.instance?.stampCurrentNode()`（内部会打 ARRIVE 并 `userFinish`）。
* 底部「结束行程」保持可见（打开原确认弹窗，可「结束并记录」或「取消行程」），作为到达按钮之外的次要入口；两者行为一致，不重复展示相同文案。
* 已打卡摘要、站点打卡弹窗在 `s.postExit` 时不显示。

### 3.3 `DemoPlayer.kt`

无需改动；新字段有默认值。演示快照可继续保持 `postExit = false`。

## 四、假设与决策

| 决策          | 结论                                             |
| ----------- | ---------------------------------------------- |
| 出站后看板       | 保留显示，进入「已到站 · 前往目的地」阶段                         |
| 自动结束判定      | 家/公司/设定目的地 150 米内驻留 3 分钟（沿用）                   |
| 计划截止时间      | **完全不参与结束判断**；出站前到点多久都不结束，出站后以 `出站 + 30 分钟` 为准 |
| 兜底结束的学习     | 不打 ARRIVE，末段步行与全程时长不学，其余数据照常                   |
| 手动结束        | 视为真实到达，打 ARRIVE(MANUAL)，参与学习                   |
| 旧 tail 静默记录 | 删除，由 postExit 阶段取代                             |
| 中途换乘下车      | 行为不变，仍进入下一段                                    |

## 五、验证

1. 编译：`compileDebugKotlin` 通过；全项目 `grep -n "\btail\b"` 无残留引用。
2. 公交末段：点「我已下车」→ 看板仍在，显示「已到站 · 前往目的地」；进入公司 150 米内 3 分钟 → 自动结束，记录含 ARRIVE。
3. 地铁末段：出站 → 看板保留；到家 3 分钟 → 自动结束；全程时长、末段步行有样本。
4. 手动结束：出站后点「已到目的地」→ 立即结束，记录含 ARRIVE(MANUAL)，学习样本正常。
5. 兜底：出站后不移动、不进目的地，30 分钟 → 自动结束；记录存在且非作废，无 ARRIVE；「算法学习」中全程时长与末段步行未新增，其它项正常。
6. 恢复：出站后强杀进程并重开 → 看板恢复为「已到站」阶段，截止时间仍为出站 + 30 分钟。
7. 结束前不出现任何到站震动/响铃（`AlightGuard` 已重置）。
8. 出站前到点：把设备时间调到计划结束时间之后、保持未出站，行程继续、看板不消失、无结束通知；再等待 1 小时仍不结束。
9. 出站前 kill 进程且截止时间已过：重开后仍能恢复该行程，不会被判为过期直接清除。
