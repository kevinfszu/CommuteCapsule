# 算法学习：卡片标题规范与数值层级重构

## 一、概述

只改「算法学习」页的排版与信息层级，不动数据与统计口径。目标：

1. 全页只保留一种标题位置（卡片内部），消除「卡外分节标题 + 卡内标题」并存。
2. 提高标题存在感，建立稳定的三级字阶：标题 → 结论 → 明细。
3. 线路卡片的「总耗时 / 平均每站」精简为「全程 / 每站」，移到卡片右上角。
4. 时长单位切换从「悬浮在区块上方」改为「从属于站间行车时长区块」，改为紧凑分段控件。

涉及文件：`app/src/main/java/com/busnotice/commute/ui/LearnScreen.kt`（主要）、`app/src/main/java/com/busnotice/commute/ui/GlassKit.kt`（不改动公共组件语义）。不改 `LearnReport.kt` / `Learn.kt` / 数据层。

## 二、现状分析

* `LearnScreen.kt` 行程页用卡内 `CardTitle`（第 163–189 行调用，第 388–389 行定义，实际是 `SectionLabel` 13sp Bold + dim）；线路页用卡外 `sectionHeader`（第 233、304 行）。同一页两套标题，正是「乱糟糟」的来源。
* 全 App 其余页面（RecordsScreen、LineEditorScreen、TripEditor、Pickers、AmapImportScreen）统一把 `SectionLabel` 放在卡片内部；只有 Settings / LocationPicker 用卡外 `sectionHeader` 做列表分组。因此本案选择「卡片内部标题」与全 App 既有约定一致。
* 现状标题仅 13sp Bold + dim，颜色最弱；结论值 17sp Bold 满色（`MetricLine` 第 421–425 行、线路「总耗时/平均每站」第 255–265 行、班次偏差第 335–337 行），导致数字比标题抢眼。
* 明细值 13sp（区间行第 292–296 行）；「样本不足」类未就绪值也是 13sp dim，没有与明细区分。
* 单位切换在 `item(key = "unit-toggle")`（第 209–220 行），位于 `sectionHeader("站间行车时长…")` 之上，视觉上像页级控件，且与页签同为 `GlassChip`，语义混淆。
* 线路卡头部只有线路牌 + 方向（第 234–246 行），指标在下方另起一行（第 247–267 行），占用纵向空间且文案是「总耗时 / 平均每站」。

## 三、设计决策

### 3.1 标题位置：统一放卡片内部

* 线路页删除两处 `sectionHeader(...)`，改为各自的 `GlassCard` 内首行标题。
* 与全 App 其余页面一致；空态也放在同一张卡内，避免出现「有标题没内容」的悬空小节。

### 3.2 字阶（本页唯一一套）

| 角色        | 字号          | 字重             | 颜色           | 用途                  |
| --------- | ----------- | -------------- | ------------ | ------------------- |
| 卡片标题      | 15sp        | SemiBold (600) | ink 78% 不透明  | 每张卡首行，卡内左对齐         |
| 正式结论      | 16sp        | Bold (700)     | ink 满色，tnum  | 时长概览三行、线路全程/每站、班次偏差 |
| 明细数值      | 13sp        | Medium (500)   | ink 90%，tnum | 站间区间值、次数后缀          |
| 行标签 / 副标签 | 14sp / 11sp | Regular        | ink / dim    | 原有不变                |
| 未就绪       | 13sp        | Regular        | dim          | 「样本不足」「—」           |

标题 15sp/600 高于正文 14sp 且不再使用最弱的 dim 色，存在感提升；结论 16sp/700 只比标题大 1sp，不会压过标题。

### 3.3 线路卡片：指标移到右上角

卡片首行改为左右两栏，右侧是一行紧凑摘要：

```
[线路牌] 往XX                 共 35.4 分钟，3.3 分钟/站
```

* 文案按要求合并为一句「共 X，Y/站」，不再使用「总耗时 / 平均每站」两个标签。
* 单位跟随分段控件：分钟 →「共 35.4 分钟，3.3 分钟/站」；秒 →「共 2124 秒，198 秒/站」。
* 缺区间时在总耗时前加「≥」：「共 ≥35.4 分钟，3.3 分钟/站」。
* 缺失降级：只有总耗时 →「共 35.4 分钟」；只有每站 →「3.3 分钟/站」；两者都无 →「—」。
* 摘要 16sp Bold tnum、右对齐、单行；移除原下方整行指标区。

### 3.4 单位切换：区块内分段控件

* 站间区块改为**一张卡片**：首行「站间行车时长」+ 右侧紧凑分段控件「分钟 | 秒」。
* 多条线路作为同一卡内的子块，块间用 12dp 间距 + 细分隔线。
* 分段控件：高 30dp、圆角 15dp、底色半透明白（深色模式 8% 白），选中段落主色填充、12sp 半粗；每段保留 48dp 最小触摸区（用 `minimumInteractiveComponentSize()` 包裹视觉体）。
* 站间无任何样本时只显示标题 + 空态说明，隐藏切换控件。
* 保留 `LearnUi.unitSec` 的跨页面记忆。

## 四、具体改动（LearnScreen.kt）

1. **字阶组件**
   * 重写 `CardTitle`：`Text(text, fontSize = 15.sp, fontWeight = FontWeight.SemiBold, color = ink.copy(alpha = 0.78f), modifier = Modifier.padding(bottom = 6.dp))`，不再调用全局 `SectionLabel`。
   * `MetricLine` 结论值字号 17sp → 16sp；未就绪值保持 13sp。

2. **行程页 4 张卡**
   * 标题保持卡内 `CardTitle`；不新增卡外标题。
   * 「时长概览」三行细色条与文案不变。

3. **线路页结构重排**
   * 删除 `item(key = "unit-toggle")` 与两处 `sectionHeader(...)`。
   * 「站间行车时长」区块：
     * `item(key = "stops")` → 一张 `GlassCard`：
       * 首行 `Row`：`CardTitle("站间行车时长")`（`Modifier.weight(1f)`，bottom padding 由内部改为 0）+ `UnitSwitch`（仅 `report.stops.isNotEmpty()` 时显示）。
       * 标题行下 6dp 间隔。
       * 若 `stops.isEmpty()`：一行 13sp dim「还没有站间打卡样本」。
       * 否则 `stops.forEachIndexed` 渲染线路子块：
         * 首个之前无分隔；其后先 `HorizontalDivider(Modifier.padding(top = 12.dp), 1.dp, Fuse.hairline(dark))` 再 12dp 间距。
         * 子块首行 `Row`：左侧 `LineBadge` + 「往X」；右侧一行摘要 `Text(summaryText, 16.sp, Bold, tnum, maxLines = 1)`：
           * `summaryText` = 非空片段用「，」拼接；
           * 总耗时片段：`"共 " + (if (s.partial) "≥" else "") + durText(total, unitSec)`；
           * 每站片段：`durText(perHop, unitSec) + "/站"`；
           * 两个都空时为 `"—"`。
         * 区间列表保留现有分隔线、`from → to`、值 + 「· N 次」、空值「—」；明细值加 `FontWeight.Medium`。
   * 「地铁班次偏差」区块：`item(key = "metros")` → `GlassCard { CardTitle("地铁班次偏差"); … }`；空态放在同一张卡内。偏差值 16sp Bold。
   * `shared-empty`（站间与班次都为空）保留一张说明卡，文案不变。
   * 顶部 `shared-hint` 文案保持「以下数据跨行程共用…空白表示还没有该区间样本。」但去掉单位切换造成的割裂感（它仍在页首说明区，不再控制单位）。

4. **UnitSwitch 组件（本文件私有）**
   * 签名 `@Composable private fun UnitSwitch(sec: Boolean, onChange: (Boolean) -> Unit, dark: Boolean)`。
   * 结构：`Row(height 30dp, clip RoundedCornerShape(15.dp), background 半透明底色, padding 3dp)`，内含两个 `Segment`：`Box(Modifier.minimumInteractiveComponentSize().clip(CircleShape).background(if selected Fuse.accent else Transparent).padding(horizontal 10dp, vertical 2dp))` + `Text(12sp, selected 时 onAccent + SemiBold)`。
   * 点击写回 `unitSec` 与 `LearnUi.unitSec`。

5. **不用改的部分**
   * 页签、渐隐遮罩、重建反馈、单位记忆、`LearnReport` 数据均保持现状。

## 五、假设与取舍

* 「标题存在感低」通过本页 15sp/600 + ink 78% 解决，不改全局 `SectionLabel`，避免影响 Records / Settings / 导入编辑等页面。
* 站间多线路合并为一张卡，长列表会更长；换取「区块—标题—控件」从属关系清晰，且与线路通常 1–3 条相符。
* 结论 16sp/700 与标题 15sp/600 仅差 1sp，数字仍可一眼扫到，但不再压过标题。
