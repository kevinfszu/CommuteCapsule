# 线路 → 站点 两级筛选选择器

## 1. 目标

添加公交、添加地铁时，统一改为「先选线路，再选站点」：

1. 第一步列出当前数据源里的全部可选线路，顶部有关键词筛选。
2. 选中线路后，列出该线路的全部站点，同样带筛选。
3. 线路、站点列表都在本地即时过滤，不发网络请求，选项多时不用手工翻找。
4. 公交的下车站选择也加筛选；「附近站点」保留为快捷入口。

## 2. 现状分析

## 3. 交互流程

**公交**
```
添加公交
 ├─ [筛选框] 线路关键词
 ├─ 附近站点（保留，位置可用时显示）
 └─ 全部公交线路 → 选线路
      → 方向 chips（多方向时）
      → [筛选框] 本站关键词 + 站点列表
      → 选上车站 → 在哪下车？([筛选框] + 列表，可跳过)
```

**地铁**
```
添加地铁
 └─ [筛选框] 线路关键词 + 全部地铁线路
      → 选线路 → 方向 chips（开往 X / 内环 / 外环）
      → [筛选框] 本站关键词 + 该方向站点列表
      → 选上车站 → 详情卡（本站首末班、分时段间隔、方向、下车站）→ 添加
```

筛选规则（统一，本地即时）：
- 归一化：去掉空白、转小写；查询词去掉末尾「路」「号线」「站」。
- 线路匹配：线路名包含关键词，或任一方向的首/末站包含关键词。
- 站点匹配：站名包含关键词。
- 关键词为空 = 全部；结果为空时显示提示文案。

## 4. 具体改动

### 4.1 数据接口（Transit.kt）

1. `LineDir` 增加方向显示名，供环线使用：
```kotlin
data class LineDir(
    val lineId: String, val firstStop: String, val lastStop: String, val label: String = "",
)
```
`label` 只在环线填 `dirLabel`（内环/外环），普通线路留空，由界面显示「开往 {lastStop}」。

2. `StaticSource` 增加带默认实现的枚举方法，避免破坏 `src/extra` 的自定义数据源：
```kotlin
fun lines(region: String): List<SearchLine> = emptyList()
```

3. `Transit` 门面增加：
```kotlin
fun lines(region: String = ""): List<SearchLine> = static.lines(reg(region))
```

### 4.2 各数据源实现 `lines`

- [JsonTransit.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/JsonTransit.kt)：
  ```kotlin
  fun lines(doc: Doc, region: String): List<SearchLine> =
      doc.lines.groupBy { it.name }.map { (name, group) ->

              isSubway = group.first().subway,
  ```

**重写 `BusPicker` 的 stage：**
```kotlin
sealed interface BusStage {
    data object Lines
    data class Station(...)                                   // 附近站点快捷入口，保留
    data class Line(val name: String, val dirs: List<LineDir>,
                    val dirIndex: Int, val query: String)
    data class Alight(val detail: LineDetail, val board: StopPoint, val query: String)

```
- `Lines`：`LaunchedEffect(Unit)` 里 `Transit.lines().filter { !it.isSubway }`；`query` 本地过滤；`query` 为空时上方显示「附近站点」分组（现有逻辑不动），下方 header「全部公交线路」；无公交线路时提示「当前数据里没有公交线路，可从附近站点进入或更换数据源」。
- `Line`：保留现有方向 chips（label 用 `LineDir.label.ifEmpty { "开往 ${lastStop}" }`）；新增筛选框，过滤 `LineDetail.stations`；点站进入 `Alight`。
- `Alight`：新增筛选框，过滤 `order > board.order` 的站点；`finish` 不变。
- `Station`（附近站点进入的线路列表）：加一个同样的筛选框，按 `p.lines` 过滤，空站台隐藏。
- 删除旧的 `query/result` 网络搜索状态与 `delay(350)` 的 `LaunchedEffect`（`nearby` 加载保留）。

**重写 `MetroPicker` 的 stage：**
```kotlin
sealed interface MetroStage {
    data object Lines
    data class Line(val line: SearchLine, val dirIndex: Int, val query: String)
    data class Station(val line: SearchLine, val dir: LineDir, val stop: StopPoint)

```
- `Lines`：`Transit.lines().filter { it.isSubway }`，`PickerOptions` 展示；行 supporting 用「首站 ⇄ 末站」；无地铁线路时提示「当前数据里没有地铁线路」。

## 5. 假设与决策

- **以「线路 → 站点」为主流程**；「附近站点」仅作为公交的快捷入口保留（用户明确要求先列线路）。
- **地铁方向在选线路阶段先选**，选站后再用 `subwayDirs` 校正方向与首末班；环线用 `dirLabel` 区分内/外环。
- **筛选为纯本地包含匹配**，不调用 `Transit.search`，无防抖延迟；不引入拼音/首字母搜索。
- **列表最多渲染 60 行**（`glassGroup` 不是懒加载），超出提示继续输入关键词；公交/地铁站点通常远低于此值。
- **排序沿用数据源顺序**（导入 JSON 的 `lines` 顺序），不做拼音排序。
- 不改数据格式、不改 `Candidate` 字段、不改 `ShuttleEditor` 与通勤车流程。`Transit.search` 继续保留给回程/实时等既有逻辑使用。
