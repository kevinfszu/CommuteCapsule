# 算法学习：数值降噪，克制使用强调

## 一、概述

「算法学习」页当前几乎每一行右侧数值都 16sp Bold 或 13sp Bold，字号、字重全面压过左侧栏目，导致页面沉重、没有重点、扫读时先看到一堆数字而不是内容。

本方案只改这一页的数值排版：**数值与左侧标签同级字号、同级字重**，用「右对齐 + 等宽 tnum + 颜色深浅」承担区分，全页唯一的强强调只保留卡片标题（`Section` 15/600）。不改数据、不改布局结构、不改其他页面。

涉及文件：`ui/Type.kt`（新增 2 个数值 token）、`ui/LearnScreen.kt`（全部数值调用点）。

## 二、现状分析（LearnScreen.kt）

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| `MetricLine` 结论值（:456-461） | `Type.Metric` 16/700 tnum，左侧标签 `Type.Body` 14/400 | 数值比标签大 2sp、重 300，四张卡共十余行，全部抢眼 |
| 时长概览三行（:167-173） | 同上 16/700 | 三行同时加粗，等于没有主次 |
| 线路卡片右上摘要（:254-258） | `Type.Metric` 16/700 | 卡片标题 15/600 反而被数字压住 |
| 区间明细值（:273-277） | `Type.MetricMini` 13/700，左侧 `Type.BodyDim` 13/400 | 同行内右侧比左侧重 |
| 班次偏差值（:310-313） | `Type.Metric` 16/700，左侧站名 14/400 | 同上，而且一行里还有线路牌 13/700 |
| 未就绪值 | `Type.BodyDim` 13 dim | 与正常值差距过大，正常值显得更重 |

页面内仍保留的合理加粗：卡片标题 `Section` 15/600、页签选中态、`重新学习`/`知道了` 按钮、`线badge` 线路牌（品牌组件，跨页一致，不改）。

## 三、设计决策

1. **数值不放大、不加粗**：正文行内数值一律 14sp / Normal，与左侧标签完全同级；靠右对齐、等宽数字、满色 ink 与左侧 78% ink 的深浅差来区分。
2. **明细行数值** 13sp / Normal tnum，与左侧 13sp dim 同字号同字重，仅靠颜色区分。
3. **全页唯一强调层**是卡片标题（15/600），其次是选中态与按钮；数字不再承担强调职责。
4. **未就绪值**保持 13sp dim，不再与正常值形成 3sp + 3 个字重的落差。
5. 不引入新的颜色，不加字距、不加背景块，避免用另一种方式制造噪音。

## 四、具体改动

### 4.1 `ui/Type.kt`

在 `BodyDim` 之后新增（不删不改现有 token，其他页面继续用 `Metric*`）：

```kotlin
/** 行内数值：与正文同级，靠等宽和右对齐区分，不再放大加粗 */
val Value = TextStyle(fontSize = 14.sp, fontWeight = FontWeight.Normal,
    fontFeatureSettings = "tnum", lineHeight = 20.sp)

/** 明细数值：与说明文字同级，只靠颜色深浅区分 */
val ValueDim = TextStyle(fontSize = 13.sp, fontWeight = FontWeight.Normal,
    fontFeatureSettings = "tnum", lineHeight = 18.sp)
```

注释里写明：「数值不使用 Metric（16/700），避免压过标题与左侧标签」。

### 4.2 `ui/LearnScreen.kt`

1. **`MetricLine`**（:424-467）
   - 左侧标签：保持 `Type.Body`，颜色改为 `ink.copy(alpha = 0.78f)`。
   - 右侧值：`if (l.ready) Type.Value else Type.BodyDim`，颜色不变（ready → ink，否则 dim）。
   - 删除「结论数字放大加粗」注释，改为「数值与标签同级，靠对齐与深浅区分」。
   - `note` 仍为 `Type.Caption`。

2. **线路卡片摘要**（:254-258）：`stopSummary(...)` 的 style 由 `Type.Metric` 改为 `Type.Value`，颜色 `ink`。

3. **区间明细值**（:273-277）：`Type.MetricMini` → `Type.ValueDim`，颜色 `ink`；左侧 `from → to` 保持 `Type.BodyDim` + dim。

4. **班次偏差值**（:310-313）：`Type.Metric` → `Type.Value`，颜色 `ink`。

5. 其他位置不动：标题 `Section`、备注 `Caption`、页签、按钮、`UnitSwitch` 选中态、线路牌均保持现状。

## 五、假设与取舍

- 「同级」按字面执行：右侧数值字号 = 左侧标签字号，字重 = Normal；不用 500/600 做「轻微强调」，避免再次滑向处处加粗。
- 不调整行高与行距，页面密度不变；视觉减重只来自字号/字重与颜色。
- 其他页面（记录、首页）的 `Metric` 数值不在本次范围，避免牵连刚统一的全局字阶。

## 六、验证

1. `gradle.bat -p e:\001-Program\CommuteCapsule assembleDebug`（签名环境变量同前，keystore 绝对路径）。
2. `adb install -r` 安装，进入「算法学习」逐页签检查：
   - 任一数值行的字号不超过左侧标签，字重不再是 Bold；
   - 页面上只剩卡片标题、选中页签、按钮是加粗；
   - 时长概览三行、线路摘要、区间明细、班次偏差的数值均靠右、等宽、满色；
   - 切换分钟/秒后排版不跳动；
   - 深色/浅色模式下数值仍清晰可读，不靠加粗也能扫读。
