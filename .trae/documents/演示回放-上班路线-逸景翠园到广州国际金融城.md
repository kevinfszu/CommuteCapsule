# 演示回放：逸景翠园 → 广州国际金融城（上班路线）

## 1. 目标

把现有「返程」演示回放替换为一条上班路线演示：从逸景翠园出发，步行到 11 号线逸景路站，乘 11 号线外环到员村，站内换乘 5 号线到科韵路，出站步行至广州国际金融城。

- 保留现有演示的播放方式：设置页两档时长、8 秒倒计时、首页看板、系统胶囊、提醒弹窗、结束行程。
- 使用真实线路与站名，时刻为模拟值，不联网、不写行程记录。
- 保留公开 API 与 `TRIP_ID = "demo-replay"`，不改动 `CommuteService`、`LiveNotifier`、`LiveBoard` 的演示判断逻辑。

## 2. 现状分析

### 2.1 当前演示实现

- [DemoPlayer.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/DemoPlayer.kt) 是一个单例播放器，硬编码一趟「地铁 5 站 + 公交 5 站」的返程行程：
  - `TRIP_ID`、`BADGE`、`trip`、`showTrips` 都是固定值。
  - `start(ctx, speed)` 先 `LiveNotifier.ensureChannels`，再倒计时 8 秒，然后按 `30× / 15×` 推进时间轴，每 250ms 刷新 `snapshot`，到点触发 `ALERTS`，最后 `finish`。
  - `frame(v)` 是纯函数，返回 `Pair<LiveSnapshot, LiveNotifier.Visual>`，是演示画面状态的唯一来源。
- 首页 [HomeScreen.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/HomeScreen.kt#L126-L130) 读取 `DemoPlayer.snapshot`、`countdown`，并用 `DemoPlayer.BADGE`、`DemoPlayer.trip`、`DemoPlayer.showTrips` 渲染。
- 看板 [LiveBoard.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/LiveBoard.kt#L242-L254) 用 `s.tripId == DemoPlayer.TRIP_ID` 隐藏节点时间轴；底部「结束行程」同样判断该 ID 后调用 `DemoPlayer.stop(ctx)`。
- 通知点击 [CommuteService.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/CommuteService.kt#L2784-L2786) 在演示中只响应「关闭」。
- 设置页 [Settings.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/Settings.kt#L116-L128) 有两行演示入口（约 1 分钟 / 约 2 分钟），启动时只传 `speed`。

### 2.2 真实线路依据

本地已有 11 号线当前运营数据 [guangzhou-11-13-current.json](file:///e:/001-Program/CommuteCapsule/data/amap/guangzhou-11-13-current.json#L55-L206)：

- 11 号线为环线，`外环` 方向从逸景路出发依次是：上涌 → 大塘 → 龙潭 → 赤沙 → 琶洲 → 员村，共 6 个区间。
- 该数据 `hopSec = 140`，6 个区间约 14 分钟。
- 逸景路站坐标约 `23.084641, 113.299718`；逸景翠园距逸景路站约 305 米，步行约 5 分钟。

5 号线员村 → 科韵路为 1 个区间，约 2 分钟；科韵路站到广州国际金融城核心区步行约 18 分钟（南都报道提到约 20 分钟，取 18 分钟作为演示值）。

## 3. 方案

### 3.1 路线与时间轴

演示时间轴（秒为当天秒数，压缩播放）：

| 常量 | 时刻 | 含义 |
|---|---|---|
| `PRE` | 08:00 | 出发前，显示倒计时 |
| `T0` | 08:03 | 现在出发，步行去逸景路站 |
| `IN` | 08:08 | 已到逸景路站，进站 |
| `RIDE` | 08:10 | 11 号线列车进站、上车 |
| `XFER` | 08:24 | 到达员村（6 站 × 约 140 秒） |
| `WALK` | 4 分钟 | 员村站内换乘步行 |
| `L5ARR` | 08:30 | 5 号线列车到站、上车 |
| `L5OFF` | 08:32 | 科韵路下车 |
| `ARRIVE` | 08:50 | 步行到广州国际金融城 |
| `END` | 08:55 | 演示结束前停留几秒 |

行程模型：

```kotlin
Trip(
    id = TRIP_ID,                 // 保持 "demo-replay"
    name = "上班",
    startMinute = 8 * 60,
    endMinute = 9 * 60,
    legs = listOf(
        Leg(
            candidates = listOf(
                Candidate(
                    type = Candidate.Type.METRO,
                    name = "11号线",
                    stopName = "逸景路",
                    lat = 0.0, lng = 0.0,
                    alightName = "员村",
                    metroDir = "外环",
                )
            ),
            rideMin = 14,
        ),
        Leg(
            candidates = listOf(
                Candidate(
                    type = Candidate.Type.METRO,
                    name = "5号线",
                    stopName = "员村",
                    lat = 0.0, lng = 0.0,
                    alightName = "科韵路",
                    metroDir = "黄埔新港",
                )
            ),
            rideMin = 2,
            transferWalkMin = 4,
        ),
    ),
)
```

`showTrips` 保留两张卡：上面是上述「上班」行程；下面是一张「下班」返程卡（5 号线科韵路 → 员村，换 11 号线内环 → 逸景路），仅用于首页演示期间占位，不参与播放。

### 3.2 文件改动

#### A. 重写 `DemoPlayer.kt`

只改演示脚本与画面状态，不改播放器结构。

1. 常量与站名
   - 删除虚构的 `METRO = "星河线"`、`BUS = "K7路"` 和两套虚构站名。
   - 新增：
     - `L11 = "11号线"`，`L5 = "5号线"`。
     - `L11_STOPS = listOf("逸景路", "上涌", "大塘", "龙潭", "赤沙", "琶洲", "员村")`。
     - `L5_STOPS = listOf("员村", "科韵路")`。
     - `ORIGIN = "逸景翠园"`，`DEST = "广州国际金融城"`。
   - `BADGE` 改为 `"演示回放 · 上班路线"`。

2. 时间常量
   - 用 `s(h, m, sec = 0)` 定义 3.1 中的 `PRE / T0 / IN / RIDE / XFER / L5ARR / L5OFF / ARRIVE / END`。
   - `WALK = 4`。
   - 删除原有 `BUS_ARR / TAP / ALIGHT / PROMPT / HOME` 等公交时间常量。

3. `trip` 与 `showTrips`
   - `trip` 按 3.1 的行程模型重写。
   - `showTrips` 改为 `listOf(trip, returnTrip)`；`returnTrip` 使用 `id = "demo-return"`，`name = "下班"`，两段地铁方向分别为 `滘口` / `内环`。

4. `frame(v)` 状态机
   保留签名 `fun frame(v: Int): Pair<LiveSnapshot, LiveNotifier.Visual>`，按以下顺序分支：

   | 条件 | leg | headline | detail | mode / 进度 |
   |---|---|---|---|---|
   | `v < T0` | 0 | `N 分钟后出发` | `按 5号线 倒推 · 08:03 出发 · 08:24 到员村换乘` | `LEAVE_LATER`，进度 `(v-PRE)/(T0-PRE)` |
   | `v < IN` | 0 | `约 N 分` | `步行约 N 分钟到逸景路 · <11号线来车>` | `METRO`，进度 `(v-T0)/(IN-T0)` |
   | `v < RIDE` | 0 | `已进站` | `逸景路 · <11号线来车>` | `METRO` |
   | `v < XFER` | 0 | `N 分钟` | `下一站 X · 08:24 到员村换乘 5号线` | 骑行，`passed` 按 `L11_STOPS` 插值 |
   | `v < XFER + WALK*60` | 1 | `换乘 5号线` | `员村站内步行约 N 分钟到 5号线站台` | `METRO` |
   | `v < L5ARR` | 1 | `等 5号线` | `5号线 约 N 分钟进站 · 下一站 科韵路` | `METRO` |
   | `v < L5ARR + 30` | 1 | `已上车` | `5号线 · 下一站 科韵路` | 骑行，`stops = L5_STOPS`，`passed = 0` |
   | `v < L5OFF` | 1 | `1 站` | `下一站 科韵路 · 约 08:32 下车` | 骑行，`stops = L5_STOPS`，`passed = 0` |
   | `v < ARRIVE` | 1 | `步行 N 分钟` | `出站后步行约 N 分钟到广州国际金融城` | 进度 `(v-L5OFF)/(ARRIVE-L5OFF)` |
   | 否则 | 1 | `已到达` | `08:50 到达广州国际金融城 · 全程约 47 分钟` | 无进度 |

   - `snap(...)` 继续复用现有 `LiveSnapshot` 构造方式；站点进度用 `stopsPassed / stopsTotal / curStop / fromStop / toStop`。
   - 新增一个「11 号线来车」文本函数，按 `RIDE - v` 计算「本趟约 N 分钟进站 / 本趟正在站内」和「下趟约 N 分钟」，间隔取 320 秒（11 号线工作日高峰）。
   - `frame` 末尾的 `Visual` 行名按阶段决定：
     - `v < XFER` → `11号线`
     - `XFER <= v < L5OFF` → `5号线`
     - `L5OFF <= v < ARRIVE` → `步行`
     - `v >= ARRIVE` → 不加行名后缀
   - `trackerRes`：地铁阶段 `ic_metro`，步行阶段 `ic_walk`；`metro` 只在步行阶段为 `false`。
   - `sub` 继续用 `"演示回放"`。

5. `ALERTS`
   按以下时刻与文案重写（格式与现有真实提醒一致）：

   | 时刻 | 标题 | 内容 |
   |---|---|---|
   | `T0` | `现在出发 · 11号线` | `步行约 5 分钟到逸景路 · 本趟约 3 分钟进站 · 下趟约 8 分钟` |
   | `IN - 60` | `即将到达 逸景路 · 11号线 约 2 分` | `步行约 1 分钟到逸景路 · 本趟约 2 分钟进站 · 下趟约 7 分钟` |
   | `IN` | `已进站 · 11号线` | `本趟约 1 分钟进站 · 下趟约 6 分钟` |
   | `XFER - 90` | `即将到达「员村」` | `请准备下车 · 下车后站内步行约 4 分钟换乘 5号线` |
   | `XFER` | `已到员村 · 换乘 5号线` | `站内步行约 4 分钟 · 5号线 6 分钟到` |
   | `L5ARR - 30` | `5号线即将到站` | `在员村站台等车 · 下一站 科韵路` |
   | `L5OFF - 60` | `即将到达「科韵路」` | `请准备下车 · 出站后步行约 18 分钟到广州国际金融城` |
   | `ARRIVE` | `已到达 广州国际金融城` | `08:50 到达 · 全程约 47 分钟` |

   地铁阶段 `metro = true`，最后到达提醒 `metro = false`。

6. 播放器部分保持原样
   - `start(ctx, speed)`、`stop(ctx)`、`finish(ctx)`、8 秒倒计时、`rate = if (speed >= 60) 30.0 else 15.0`、250ms 刷新、到 `END` 后停 5 秒退出，都保留。
   - `TRIP_ID` 不变，避免改 `LiveBoard` / `CommuteService` 的演示判断。

## 4. 假设与决策

1. **真实站名、模拟时刻**：按用户选择，演示使用真实线路与站名；所有到站、发车间隔、步行时间均为演示值，不接实时数据。
2. **替换而非新增**：现有「返程」演示被替换，不新增第二条演示入口，`Settings` 仍只有两档时长。
3. **11 号线方向**：按本地 `guangzhou-11-13-current.json` 的 `外环` 方向，逸景路 → 上涌 → 大塘 → 龙潭 → 赤沙 → 琶洲 → 员村，6 个区间。
4. **5 号线方向**：员村 → 科韵路，往黄埔新港方向，1 个区间。
5. **最后一段步行**：模型没有 WALK 类型，因此不新增 `Leg`；在 `frame` 的最后一屏用「步行 N 分钟」和进度条表现，与现有演示到站后的处理方式一致。
6. **公开 API 不变**：`TRIP_ID`、`trip`、`showTrips`、`snapshot`、`countdown`、`running`、`start`、`stop`、`frame` 签名全部保留，避免联动改动。
7. **时长**：时间轴 08:00–08:55，30× 约 1 分 50 秒，15× 约 3 分 40 秒；设置页现有「约 1 分钟 / 约 2 分钟」文案保留不动。
8. **数据许可与仓库声明**：源码将出现真实站名，README 中「不含真实站名」的表述必须同步修改；`data/` 仍不提交。
