# 出站差值用于倒推下车时间

## 摘要

修正上一轮的表述与实现偏差：「下车→出站」的实际差值继续累积样本，但它的用途不是统计展示，而是**终点站忘记人工打卡时，用出站时间倒推下车时间**。即在 `ALIGHT = EXIT − 差值` 里，差值优先取学到的实测中位数，样本不足才回退到用户在编辑页填的预设。

方向仍然单向：出站只来自刷卡/基站，绝不由下车推算。

## 现状分析

- [NodeLog.kt L171-L176](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/NodeLog.kt#L171-L176) 已有正确公式：`ALIGHT = EXIT − Anchors.alightEstimateSec`。
- [CommuteService.kt L650](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/CommuteService.kt#L650) 目前把 `alightEstimateSec = trip.alightEstimateSec` 直接传进去，只用用户预设，没有用学到的值。
- [CommuteService.kt L688](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/CommuteService.kt#L688) `recordNode(EXIT_WALK, ...)` 在正常结算，样本一直在积累；`Metric.EXIT_WALK` 要求 ≥5 个样本。
- 上一轮删除了 `Learn.exitWalkSec()`，导致样本只有写入没有读取。
- 其他指标（乘车、换乘步行、末段步行）都是「学习值优先、预设兜底」，这里沿用同一约定。

## 改动方案

### 1. 恢复读取：Learn.exitWalkSec

文件：`app/src/main/java/com/busnotice/commute/Learn.kt`

在 `transferWalkSec()`（L235-L236）之后恢复：

```kotlin
/** 最后一段：下车比出站早多少秒；样本不足返回 null，由预设兜底 */
fun exitWalkSec(ctx: Context, tripId: String, legIdx: Int) =
    nodeSec(ctx, Metric.EXIT_WALK, "$tripId#$legIdx")
```

### 2. 结算时优先用学习值

文件：`app/src/main/java/com/busnotice/commute/CommuteService.kt`

`settleNodes()` 的 `NodeLog.Anchors(...)`（L643-L655）把：

```kotlin
alightEstimateSec = trip.alightEstimateSec,
```

改为：

```kotlin
// 下车比出站早多少：优先用实测中位数，样本不足用编辑页预设
alightEstimateSec = Learn.exitWalkSec(this, trip.id, trip.legs.lastIndex)
    ?: trip.alightEstimateSec,
```

只取最后一段：出站节点只存在于最后一段地铁，中间段的 `ALIGHT` 由换乘步行或下一段上车时间推算，不经过这个值。

## 决策与假设

- **优先级**：学到的实测中位数优先于用户预设，与乘车时长、换乘步行、末段步行一致；样本不足（<5）时用预设。
- 出站仍只来自刷卡（`TAP`）或基站（`AUTO`），不会因为这条改动被反推。
- 学习的样本仍允许 `ALIGHT` 为估算值（用户上一轮已确认这个差值足够固定），所以忘记打卡的日子也会贡献样本。
- 倒推只作用于最后一段地铁；公交没有出站节点。
