# 通勤胶囊：「节间时长」补全与上车时刻积累

## 概要

1. 「算法学习」里的「节点时长」改名「节间时长」。
2. 补全节间时长：**优先用人工打卡/刷卡/补录的节点**；同一趟行程里没有人工节点时，**退而用定位/基站自动识别的节点**参与学习。同时补上自动进站时间戳，让「进站→上车」有样本。
3. 积累上车时刻：始发站与换乘站都学「几点上车」，并在**上车前**用历史时刻兜底提示「下一班约 HH:MM 到」（实时/时刻表优先，历史仅兜底）。
4. 新增「行程段时长」指标（第 1 段：进站/出发→下车；换乘段：上一段下车→本段下车，含换乘步行+候车）。
5. 站间行车时长维持「只认逐站打卡」，不补平均样本（按用户选择）。

```kotlin
/**
 * 用该段历史「几点上车」的样本，取今天还没到的最近一个时刻作为下一班到站时间。
 * 样本不足 2 天或今天已全部错过 → null（交给实时/时刻表兜底，不硬凑明天）。
 */
fun nextBoardClockAt(ctx: Context, tripId: String, legIdx: Int, now: Long): Long? {
    val mins = boardClockEntries(ctx, tripId, legIdx).map { it.second }
    if (mins.size < BOARD_CLOCK_MIN_SAMPLES) return null
    val zone = ZoneId.systemDefault()
    val day = Instant.ofEpochMilli(now).atZone(zone).toLocalDate()
    return mins.sorted().asSequence()
        .map { day.atTime(it / 60, it % 60).atZone(zone).toInstant().toEpochMilli() }
        .firstOrNull { it > now }
}
```

## 假设与决策

- 学习来源按用户选择：**人工（手动/刷卡/补录）优先；该节点没有人工值时用定位/基站自动识别值补位**；界面推算值（`ESTIMATED`）永不参与学习。
- 自动进站只在「推断出进站时刻」时补一个 `ENTER(AUTO)`，刷卡/手动会追加覆盖；不新增任何提醒或状态。
- 「下一班约 HH:MM 到」：实时公交、时刻表、地铁班表优先；都给不出时，用该段历史「几点上车」的下一时刻兜底；今天已错过则返回空，不显示明天的时刻。
- 「行程段时长」定义：首段 = 进站（无进站则出发）→ 下车；换乘段 = 上一段下车 → 本段下车，因此天然包含换乘步行与候车。
- 「站间时长」只保留逐站打卡样本（用户选择），不补平均样本。
- 上车时刻样本仍只来自人工/刷卡上车（自动上车的时刻可能偏晚，不作为时刻学习来源）。
