# 算法学习：取消时长类 3 次样本门槛

## Summary

把「算法学习」里**时长类**样本门槛降到 1 个样本：站间行车时长、每段乘车时长、节点时长（候车 / 换乘步行 / 出站步行 / 末段步行 / 反应时长）第一次实测就参与预测。**保持不变**：习惯上车时刻（同星期几 3 天 / 总体 5 天）、首末段步行 3 次、家与公司 3 票确认、时间窗自动调整（6 个样本 / 4 天）。

界面同步改为「已学到 · N 次样本」，不再显示「N/3」「样本不足」这类等待提示。

## Proposed Changes

### 1. [Learn.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/Learn.kt)

**做法**：只改门槛数值与对应注释，不动数据存储结构和写入逻辑。

- L265-271 `Metric` 全部改为 1：

```kotlin
enum class Metric(val minSamples: Int, val range: IntRange) {
    WAIT(1, 0..1200),        // 进站 → 上车
    TRANSFER(1, 0..1200),    // 下车 → 下一段上车
    EXIT_WALK(1, 0..900),    // 下车 → 出站
    LAST_WALK(1, 60..2400),  // 出站/下车 → 到达
    REACT(1, 10..300),       // 首次提醒 → 确认下车
}
```

保留 `minSamples` 字段：`nodeSec`（L298）与 `nodeStat`（L417）仍用它判断，值变成 1 即可。

- L182-187 `rideMin`：

```kotlin
/** 第一次实测后就用中位数；样本越多越稳 */
fun rideMin(ctx: Context, tripId: String, legIdx: Int): Int? {
    val l = (ctx.getSharedPreferences(RIDE, Context.MODE_PRIVATE).getString("$tripId#$legIdx", "") ?: "")
        .split(',').mapNotNull { it.trim().toIntOrNull() }
    return if (l.isEmpty()) null else l.sorted()[l.size / 2]
}
```

- L332 `stopMedian`：`if (l.isEmpty()) null else l.sorted()[l.size / 2]`；L373 注释「至少 2 个样本」改为「至少 1 个样本」。
- L413 `rideStat`：`Stat(values, 1)`。
- L442-443 `stopStats`：`Stat(avgs[line].orEmpty(), 1)`、`Stat(v, 1)`。

**为什么**：这五个读取点覆盖用户点名的全部时长类数据，`Stat.need` 与 `Metric.minSamples` 只是报表阈值，没有其它调用方依赖具体数值。

## Assumptions & Decisions

1. 「站点之间的时长」= `stopPerHopSec` / `stopPairSec` / `stopPairTable`（共用 `stopMedian`），门槛 2 → 1。
2. 「换乘步行」= `Metric.TRANSFER`（节点指标），不是 `WalkLearn` 的首末段步行；后者按「其余保持原样」仍为 3 次。
3. 首样本直接生效，不加偏移限制（用户选择）。异常样本通过「行程记录删除 → 学习样本回滚」纠正，现有 journal 机制已支持。
4. 习惯上车时刻是唯一影响自动唤起的行为，保持 3 天 / 5 天不变，避免一天异常就把唤起时间挪 40 分钟。
5. `Stat.need` / `Metric.minSamples` 字段保留（值为 1），不做结构重构。
6. 时间窗自动调整 `suggest` / `autoAdjust` 不动：单样本时分位数会塌缩、会把窗口压到最小 30 分钟，风险大于收益。
7. 不推 GitHub，按用户最新要求本地构建后 `adb install -r` 到手机验证。
