# 演示回放贴合真实行程（只保留 1 分钟版）

## 摘要

把演示回放从「独立的简化动画」改造成「复用真实行程看板与提醒逻辑的 1 分钟录屏脚本」：

- 只保留一个入口，固定 30× 播放，约 1 分钟（含 5 秒倒计时）。
- 演示看板补齐真实 UI：节点时间轴、「确认上车 / 到站打卡 / 我知道了 / 我已下车」、已打卡摘要与撤销。
- 演示中的按钮真的能点：点击后按真实逻辑推进演示，不读写本机行程记录。
- 看板文案、胶囊标题、到站提醒全部对齐真实 `Decision` / `AlightGuard` 口径。
- 系统通知上的按钮（确认上车 / 停止本次下车提醒 / 确认下车）在演示中同样生效。

## 现状与差异

| 项目 | 真实 App | 现在的演示回放 | 处理 |
|---|---|---|---|
| 已确认下车 | `alightDue` 时看板出现「我知道了 / 我已下车」 | `snap()` 从不设置 `alightDue`，永远不出现 | 按站点进度设置 `alightDue` |
| 动作行 | 等车显示「确认上车」；乘车显示「到站打卡」+ 到站两个按钮 | `LiveBoard` 用 `if (!demo)` 整行隐藏 | 演示也显示，并绑到 DemoPlayer |
| 节点时间轴 | 出发/进站/上车/下车/换乘/出站/到达 | 演示整段隐藏 | 显示模拟节点，当前节点高亮，只读 |
| 已打卡摘要 | 乘车中显示「已打卡 N 站 · 最近 X HH:mm」+ 撤销 | 无数据 | 演示可打卡并显示 |
| 到站提醒 | 「下一站下车「员村」」/「现在下车「员村」」 | 「即将到达「员村」」「已到员村 · 换乘 5号线」等 | 改用 `AlightGuard.title/text` |
| 乘车看板 | 「约 3 分」/「即将到达」+「当前 X · 下一站 Y · 距 Z 还有 N 站」 | 「3 分钟」+「下一站 X · 08:30 到员村换乘」 | 对齐真实句式 |
| 胶囊标题 | 「11号线 · 逸景路」「11号线 · 赤沙 → 琶洲」 | 「5 分钟后出发 · 11号线」 | 对齐真实句式 |
| 时长入口 | — | 设置页两行：约 1 分钟 / 约 2 分钟 | 只保留 1 分钟 |

## 方案

### 1. 时间轴：压到 1 分钟

固定 `RATE = 30.0`、`COUNTDOWN = 5`。模拟时间轴 `PRE → END` 共 29 分钟，播放约 58 秒，加倒计时约 63 秒。

| 常量 | 时刻 | 含义 |
|---|---|---|
| `PRE` | 08:09 | 出发前倒计时 |
| `T0` | 08:12 | 现在出发，步行 4 分钟去逸景路 |
| `IN` | 08:16 | 已到逸景路站、进站 |
| `RIDE` | 08:18 | 11 号线到站、上车 |
| `XFER` | 08:28 | 到员村（6 站约 10 分钟） |
| `L5ARR` | 08:31 | 站内步行 3 分钟后上 5 号线 |
| `L5OFF` | 08:33 | 科韵路下车（1 站约 2 分钟） |
| `ARRIVE` | 08:37 | 出站步行 4 分钟到广州国际金融城 |
| `END` | 08:38 | 停 5 秒后退出 |

同步把 `trip.legs[0].rideMin` 改为 10、`legs[1].rideMin` 改为 2、`transferWalkMin = 3`（只影响行程卡展示）。

### 2. DemoPlayer：可交互的演示状态

改造 [DemoPlayer.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/DemoPlayer.kt)：

- `start(ctx: Context)`：去掉 `speed` 参数与 15× 分支；启动时重置所有演示状态（打卡、静音、节点、提醒触发记录、播放原点）。
- 新增只读状态流，供 `LiveBoard` 渲染，**不写本机记录**：
  - `nodes: MutableStateFlow<List<NodeLog.Stamp>>`
  - `currentNode: MutableStateFlow<NodeLog.NodeRef?>`
  - `stopChoices: MutableStateFlow<List<String>>`
  - `stopMarksUi: MutableStateFlow<List<StopMark>>`
- 新增交互方法（行为与真实服务一致，内部分支不读写行程数据）：
  - `onBoarded()`：等车/换乘步行时调用，跳到 `RIDE`；换乘步行时跳到 `L5ARR`。
  - `ackAlight()`：11 号线只剩 1 站时跳到 `XFER`；5 号线乘车中跳到 `L5OFF`。
  - `muteAlarm()`：记下「当前段 + 当前阶段」，抑制该阶段后续提醒（与真实一致：不改 `alightDue`、不记时间）。
  - `markStop(idx)` / `undoLastStopMark()`：仅 11 号线乘车中可打卡；写入演示内存，时间用模拟时刻。
- 内部跳转统一走 `jump(target)`：重设播放原点，并把 `at <= target` 的提醒标记为已触发，避免跳段后一次性补弹。
- 节点生成规则（时间使用今天的日期 + 模拟时刻，节点来源 `Src.AUTO`）：
  - 出发 `T0`、进站1 `IN`、上车1 `RIDE`、下车1 `XFER`、上车2 `L5ARR`、下车2 `L5OFF`、出站2 `L5OFF+60s`、到达 `ARRIVE`。
  - 当前节点：`v < IN` 进站 → `v < RIDE` 上车 → `v < XFER` 下车 → `v < L5ARR` 上车2 → `v < L5OFF` 下车2 → 到达。
- 可打卡站点：11 号线乘车时为 `L11_STOPS.dropLast(1)`（6 个），5 号线乘车时为 `["员村"]`。

### 3. `frame(v)` 文案对齐

按真实 `LiveSnapshot` / `Visual` 口径重写各阶段：

- 出发前：`3 分钟后出发`，详情 `08:12 出发 · 步行 4 分钟到逸景路 · 本趟 08:18 进站`。
- 步行到站：`约 4 分`，详情 `步行约 4 分钟到逸景路 · 本趟约 X 分钟进站 · 下趟约 Y 分钟`。
- 已进站：`约 2 分`（≤1 分钟时 `进站`），详情 `已到 逸景路 · …`。
- 11 号线乘车：`约 X 分`；过了最后一个中间站（琶洲）后改 `即将到达`；详情 `当前 赤沙 · 下一站 琶洲 · 距 员村 还有 2 站`；`alightDue = 只剩 1 站`。
- 换乘步行：`约 3 分`，详情 `步行约 3 分钟到 员村 · 本趟约 X 分钟进站 · 下趟约 Y 分钟`。
- 5 号线乘车：`即将到达`，详情 `当前 员村 · 下一站 科韵路 · 距 科韵路 还有 1 站`；`alightDue = true`。
- 出站步行：`约 4 分`，详情 `出站后步行约 4 分钟到 广州国际金融城`。
- 到达：`已到达`，详情 `08:37 到达 广州国际金融城 · 全程约 25 分钟`。
- 胶囊标题改为真实格式：`11号线 · 逸景路`、`11号线 · 赤沙 → 琶洲`（临近时 `11号线 · 即将到达 员村`）、`步行 · 前往广州国际金融城`；`sub` 改为 `上班 · 第 N/2 段`。

## 假设与决策

- 用户已确认：按钮可交互；结尾保留出站步行 + 已到达；演示显示模拟节点时间轴。
- 演示仍不读写本机行程记录、不联网，站名真实、时刻模拟。
- 1 分钟是「约 1 分钟」：58 秒正片 + 5 秒倒计时；不靠提高倍速硬压，保证文案可读。
- 「我知道了」在真实 App 中只停止重复响铃；1 分钟演示里没有重复响铃，因此点击后保持按钮与 `alightDue` 不变（与真实一致），只在提醒尚未触发时抑制该阶段提醒。
- 5 号线只有 1 站，按真实逻辑一上车就进入「只剩 1 站」：`alightDue` 从上车起为 true，并立即弹「下一站下车「科韵路」」。

1. `gradle testDebugUnitTest`（JDK 17 + 项目虚拟环境不需要；纯 JVM 单测）。
2. 本地 `assembleDebug` 并 `adb install -r` 到手机（按既有约定，不推 GitHub）。
3. 手机上从「设置 → 演示回放（约 1 分钟）」启动，确认：
   - 首页出现「演示回放 · 上班路线」徽标与看板，时长约 1 分钟。
   - 等车阶段有「确认上车」，点击后直接进入乘车；11 号线只剩员村 1 站时出现「我知道了 / 我已下车」；点击「我已下车」进入换乘。
   - 节点时间轴随进度逐项出现并高亮当前节点；乘车中点「到站打卡」可打卡并显示摘要/撤销。
   - 5 号线一上车即出现到站按钮；点「我已下车」进入出站步行，最后停在「已到达」。
   - 胶囊标题为「线路 · 站名」「线路 · 当前站 → 下一站」；到站弹窗为「下一站下车「X」」「现在下车「X」」。
   - 通知栏按钮「点击通知 确认上车 / 停止本次下车提醒 / 确认下车」在演示中生效。
4. 真实行程期间设置页演示入口仍不可用（`tripOn` 判断保留）。
