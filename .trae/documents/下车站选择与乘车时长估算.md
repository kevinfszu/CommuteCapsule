# 下车站选择与「大约坐多久」估算

## Summary

本轮做两件事：

1. **下车站复用可筛选的站点列表**：公交已有下车站筛选列表；地铁下车站目前是文本框，改为与上车站一致的「同线路站点列表 + 关键词筛选」，不重新选线路和方向。
2. **按站数估算「大约坐多久」并允许调整**：选定下车站后，用「相隔站数 × 每站用时」算出分钟数并显示，再提供步进器让用户微调；添加线路时把这个值写入 `Leg.rideMin`。

## Current State Analysis

- 公交流程 [Pickers.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/Pickers.kt)：`Lines → Line(选上车站) → Alight(选下车站，带筛选)`；`Alight` 点击站点直接 `finish(...)` 并 `onPicked(Candidate)`，没有估时步骤。`finish` 内按站名匹配下车站坐标。
- 地铁流程 [Pickers.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/Pickers.kt)：`Lines → Line(选上车站) → Station(方向、首末班、间隔)`；`Station` 里的下车站是 `GlassField` 文本（`alight` 字符串），无法从列表选、也拿不到坐标与站数。
- 「大约坐多久」的唯一落地字段是 [Model.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/Model.kt#L157-L163) 的 `Leg.rideMin`；编辑页已有 1–120 分钟步进器 [TripEditor.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/TripEditor.kt#L365-L368)，`Stepper` 是 public 可复用。
- `Candidate` 本身没有乘车时长；[App.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/App.kt#L26-L35) 的 `addCandidate` 只追加候选，不碰 `rideMin`。
- 每站用时：`JsonTransit.Line` 有真实 `hopSec`（地铁默认 140 秒、公交默认 90 秒），`metroRoute.durSec` 也用它；但对外暴露的 `LineDetail` 没有这个字段，选择器拿不到。
- `Stepper(label, value, min, max, unit, onChange)` 在 [TripEditor.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/TripEditor.kt#L513-L528)，选择器可直接调用。
- `ShuttleEditor` 的保存调用是 `addCandidate(s.legIndex, it, s.candidateIndex)`（第三位是 `replaceAt`），调整函数签名时必须改命名参数。

## Proposed Changes

### 1. `Transit.kt`：`LineDetail` 带每站用时

- `LineDetail` 末尾新增 `val hopSec: Int = 0`（0 = 数据源没提供，界面用回退值）。放在最后并给默认值，避免改动所有构造点与示例源编译。

### 2. `JsonTransit.kt` / `MockSource.kt`：填充 `hopSec`

- `JsonTransit.lineDetail(...)` 构造 `LineDetail` 时传 `hopSec = line.hopSec`。
- `MockSource.lineDetail(...)` 传 `hopSec = HOP_S`（90 秒）。
- `examples/json-source/.../JsonSource.kt` 不改（用默认 0，走回退值）。

### 3. `Pickers.kt`：估时函数 + 公交确认页 + 地铁列表化下车站

新增纯函数（`internal`，便于单测）：

```kotlin
internal fun estRideMin(hops: Int, hopSec: Int, fallbackSec: Int): Int =
    if (hops <= 0) 0 else ((hops * (hopSec.takeIf { it > 0 } ?: fallbackSec) + 59) / 60).coerceIn(1, 120)
```

回退每站用时：公交 `120` 秒、地铁 `140` 秒。

#### 3.1 公交

- `BusStage.Alight` 增加 `back: BusStage`，返回时回到进入 Alight 前的阶段（线路站点列表或附近站点），避免重选线路后丢失方向 chips。
- 新增 `BusStage.Confirm(detail, board, alight: StopPoint, rideMin: Int, back: BusStage)`：
  - 从 `Alight` 点某站进入，初始 `rideMin = estRideMin(alight.order - board.order, detail.hopSec, 120)`。
  - 页面显示线路、上/下车站、`相隔 N 站 · 约 M 分钟`，并用 `Stepper("大约坐多久", rideMin, 1, 120)` 允许调整。
  - 「添加」调用 `finish(detail, board, alight, rideMin)`；返回键回到同一 `Alight`（保留原 `back` 与筛选词可清空）。
- `finish(d, b, alight: StopPoint?, rideMin: Int)`：`alight == null` 时 `rideMin` 传 0。
- `Alight` 顶部卡片的「跳过」仍直接 `finish(..., null, 0)` —— 不选下车站就没有站数可估，保持 `Leg.rideMin` 原值。
- `BusPicker` 的 `onPicked` 改为 `(Candidate, Int) -> Unit`。

#### 3.2 地铁

- 删除 `MetroPicker` 顶层的 `var alight` 字符串与 `GlassField` 文本框。
- 阶段定义改为：

```kotlin
private sealed interface MetroStage {
    data object Lines : MetroStage
    data class Line(val line: SearchLine, val dirIndex: Int, val query: String) : MetroStage
    data class Station(
        val line: SearchLine, val dirIndex: Int, val dirDest: String,
        val stop: StopPoint, val dirLineId: String,
        val alight: StopPoint?, val hops: Int, val rideMin: Int,
    ) : MetroStage
    data class Alight(val back: Station, val dirLineId: String, val dirDest: String, val query: String) : MetroStage
}
```

- 进入 `Station` 时 `dirDest = ""`、`dirLineId = line.dirs[dirIndex].lineId`、`alight = null`、`hops = 0`、`rideMin = 0`。
- `Station` 内方向 chips 的点击改为 `stage = s.copy(dirDest = item.dest, dirLineId = item.dirId, alight = null, hops = 0, rideMin = 0)`（换方向后原下车站与估时失效）；方向选中值仍用现有 `sel` 推导逻辑。
- `Station` 卡片里把文本框换成可点击行：
  - 未选：`下车站（可选）　去选 ›`
  - 已选：`下车站：${alight.name}　相隔 N 站`
  - 点击进入 `MetroStage.Alight(s, 当前方向的 dirLineId, 当前方向名, "")`。
- `Alight` 阶段：按 `dirLineId` 拉 `Transit.lineDetail`（`LaunchedEffect` + loading/失败提示，复用 Line 阶段写法），用 `PickerOptions` 展示 `stations.filter { it.order > back.stop.order && nameMatches(it.name, query) }`：
  - title：`"${back.stop.name} · 选下车站"`，placeholder「筛选下车站」。
  - 行 supporting：`"${st.order - back.stop.order} 站 · 约 ${estRideMin(...)} 分钟"`。
  - leading：线路/上车站摘要 + 「跳过」按钮（返回 `back`，不改估时）。
  - 点某站：`stage = back.copy(alight = st, hops = st.order - back.stop.order, rideMin = estRideMin(...), dirDest, dirLineId)`。
- 回到 `Station` 且 `alight != null` 时，在下车站行下方显示 `相隔 N 站 · 大约坐多久` + `Stepper(..., s.rideMin, 1, 120) { stage = s.copy(rideMin = it) }`；调整只改本次添加值。
- 「添加」按钮：
  - `alightName = s.alight?.name.orEmpty()`，并写入 `alightLat/alightLng`（有下车站时），让后续 `MetroRoutes` 能直接算路线。
  - `onPicked(candidate, if (s.alight != null) s.rideMin else 0)`。
- `MetroPicker` 的 `onPicked` 改为 `(Candidate, Int) -> Unit`。

### 4. `App.kt`：把估时写进 `Leg`

```kotlin
fun addCandidate(legIndex: Int, c: Candidate, replaceAt: Int = -1, rideMin: Int = 0)
```

- 追加/替换候选后，`rideMin > 0` 时把该段 `Leg.rideMin` 设为 `rideMin`；`rideMin <= 0` 保持原值。
- 两处选择器改为 `onPicked = { c, ride -> addCandidate(s.legIndex, c, rideMin = ride) }`。
- `ShuttleEditor` 改为 `onDone = { addCandidate(s.legIndex, it, replaceAt = s.candidateIndex) }`（改成命名参数）。

## Assumptions & Decisions

- **不重选线路**：地铁下车站只在上车时已选线路/方向内选；方向在 `Station` 卡片改，下车站列表随方向切换。
- **只在下车站确定后估时**：跳过下车站时不猜时长，保持 `Leg.rideMin` 原值（默认 10 分钟），避免估算污染换乘段。
- **估算优先真实数据**：`hopSec > 0` 用数据源每站用时；否则公交按 120 秒/站、地铁按 140 秒/站回退。结果向上取整，限制 1–120 分钟。
- **估时随选择自动写入**：用户不调整时直接用估算值；调整后以调整值为准（写入 `Leg.rideMin`）。
- 公交下车站仍只允许上车站之后的站（`order > board.order`）；地铁同理，不支持坐反方向。
- 地铁下车站列表不做跨线路换乘查询，仅当前线路当前方向的后续站。
