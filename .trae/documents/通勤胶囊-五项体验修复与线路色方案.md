# 通勤胶囊：7 项体验修复 + 地铁线路色方案

## 一、任务范围

1. 出站打卡、首页看板隐藏后，「最近行程」立即刷新为本次行程。
2. 最近行程支持人工修正节点时间，修正结果回写记录并重算该记录的算法学习样本。
3. 点了「我已下车」后，即使没点「我知道了」，也不再重复震动/响铃。
4. 行程记录详情里，首站（确认上车）与末站（我已下车）也显示为到站打卡时间。
5. 行程详情 / 算法学习中的地铁线路名使用线路特征色（彩色线路牌）；算法学习-线路的站间时长按行车方向站序排列，并列出全部区间、缺样本留空。
6. 点「我知道了」后有明确反馈，且该按钮立即隐藏，直到提醒阶段升级再出现。
7. 只剩本段下车站（`alightDue`）时不再显示「到站打卡」，该站由「我已下车」一并完成。

已确认的设计决策：
- 线路色样式：**彩色线路牌**（圆角色块 + 白/黑字，与首页看板 `LineBadge` 一致）。
- 人工修正入口：**仅首页「最近行程」**，行程记录详情保持只读。

构建方式：本机已连接手机（`e0a734eb`，已装 `0.4.13-local`/413），本次按你的明确要求本地编译并 `adb install -r`，版本用 `0.4.14-local`（414）。

## 二、现状分析（关键位置）

| 问题 | 现状与根因 |
| --- | --- |
| 1 最近行程不刷新 | `CommuteService.endTrip()` 在到站时先把 `LiveState.snapshot` 置空（看板消失），而行程记录要等到尾程结束 `finish() → settleNodes()` 才写入。`HomeScreen` 的 `lastRun` 只在 `resumeTick/liveId` 变化时重读，之后记录写入没有任何信号触发重读，于是一直显示上一条。`ackAlight()` 在 `endTrip()` 之后又调 `saveRun()`，还会把已清空的 `run_state` 写回来，导致首页可能继续显示「正在恢复」。 |
| 2 修正不参与学习 | `RecentRunCard` 已支持点按节点改时间，但写入用 `NodeLog.updateLast()`，仅改记录，不重算 `Learn` 样本；来源是 `BACKFILL`。 |
| 3 下车后仍震动 | `ackAlight()` 先设 `alightAckedAt=now`，随后 `markAlight()` → `resetAlightGuard()` 把 `alightAckedAt` 清零；轮询里 `fireAlight()` 因此不再被拦截，末段地铁在站内等待出站期间会再次响铃/震动。 |
| 4 首末站空 | `RecordsScreen.RecordDetail` 的「到站打卡」只读 `r.marks`，首站（上车）和末站（下车）没有人工打卡就显示 `—`。学习侧 `Learn.recordStops()` 在 `marks` 为空时直接 `return`。 |
| 5 线路色/排序 | `LearnReport.stopStats()` 的区间按 prefs 键遍历顺序输出（无序），`LearnReport` 还 `.take(8)`；行程段与算法学习里的线路名都是纯文本。`Transit.colorOf(name)` 已存在且带缓存，`ui.lineColor(null, name)` / `LineBadge()` / `shortLine()` 可直接复用。 |
| 6 静音无反馈 | `muteAlarm()` 只把 `alarmMutedStage` 记为当前阶段，`LiveSnapshot` 没有把「已静音」传给界面；`LiveBoard` 仍按 `s.alightDue` 一直显示「我知道了」，点了没有任何视觉变化。 |
| 7 到站打卡冗余 | `LiveBoard` 在 `s.alightDue`（只剩下车站）时仍同时显示「到站打卡」「我知道了」「我已下车」三个按钮；此时「到站打卡」列的站点不含下车站，点了也只是选中其它站，语义重复。 |

## 三、改动方案

### 问题 1：最近行程实时刷新

**A. `NodeLog` 增加变更信号与按 id 更新**

- 新增 `val revision = MutableStateFlow(0L)`；在 `writeHistory()` 末尾 `revision.value++`，旧版 `LAST` 分支更新时也自增。
- `saveLastRun(...)` 改为返回新记录 `id: String`（`writeHistory` 后 `return rec.id`）。
- 新增：

```kotlin
fun updateRecord(ctx: Context, id: String, nodes: List<Stamp>, learned: List<String>? = null): Boolean {
    val all = records(ctx).toMutableList()
    val i = all.indexOfFirst { it.id == id }
    if (i < 0) return false
    all[i] = all[i].copy(nodes = nodes, learned = learned ?: all[i].learned)
    writeHistory(ctx, all)
    return true
}

fun lastRecord(ctx: Context, now: Long = System.currentTimeMillis()): RunRecord? =
    records(ctx, now).firstOrNull()?.takeIf { now - it.savedAt <= LAST_KEEP_MS }
```

- 删除 `lastRun()`（仅首页使用）；`updateLast()` 改为仅给旧 `LAST` 兜底或直接删除（首页改用问题 2 的修正接口）。

**B. 服务端：到站即落一条记录，尾程结束再更新同一条**

- 新增字段：`private var settledId: String? = null`、`private var settledNodes: List<NodeLog.Stamp> = emptyList()`；在 `onStart` 新行程初始化区（约 367 行）重置为 `null/emptyList`。
- `settleNodes(aborted)` 改为：
  - `val raw = settledNodes + NodeLog.raw(...)`（第一次结算时 `settledNodes` 为空，等价原逻辑）。
  - 解析、`learnNodes` 后：
    - `learned = (NodeLog.record(settledId)?.learned ?: emptyList() if 已结算 else emptyList()) + Learn.endJournal()`，去重保序；
    - 首次：`settledId = NodeLog.saveLastRun(..., learned = learned)`；之后：`NodeLog.updateRecord(settledId, nodes, learned)`。
  - 记录 `settledNodes = nodes`，最后 `NodeLog.clearActive`。
  - 说明：尾程中 `learnLastWalk()` 会 `stamp(ARRIVE)`，`NodeLog.stamp` 会在 ACTIVE 为空时重建键，因此尾程结束时 `NodeLog.raw()` 能取到新的 ARRIVE；第一次结算 `ARRIVE` 是 ESTIMATED 不学，第二次才写入 `LAST_WALK/TRIP`。
- `endTrip()`：在 `placeVotes()` 之后、`tail = true` 之前调用 `settleNodes(aborted = false)`。这样看板一消失，首页就能读到今天的记录。
- `finish(cancelled = true)`：若 `settledId != null`，先 `NodeLog.deleteRecord(this, settledId!!)` 再清理，避免中途取消留下半条记录。
- `ackAlight()`：末尾 `saveRun(deadlineAt)` 改为 `if (!tail) saveRun(deadlineAt)`，避免 `endTrip` 清空后又把 `run_state` 写回、首页误显示「正在恢复」。

**C. `HomeScreen` 订阅变更**

- `val rev by NodeLog.revision.collectAsState()`；
- `LaunchedEffect(resumeTick, liveId, rev) { lastRun = NodeLog.lastRecord(ctx)?.takeIf { ... } }`（过滤条件沿用 `real >= 2 && span >= 2 分钟`，改为读 `r.nodes`）；
- `lastRun` 类型改为 `NodeLog.RunRecord?`；渲染处 `RecentRunCard(r.trip, r.nodes, recordId = r.id, ...)`。

效果：到站（含「我已下车」→ 出站）→ 看板隐藏的同时写入记录 → revision 触发重读 → 「最近行程」立即变成今天这趟；尾程结束后再以最终节点更新同一条（不会出现两条记录）。

### 问题 2：最近行程人工修正并回写学习

- `LiveBoard.RecentRunCard` 增加参数 `recordId: String`；把 `onLongPress` / `onDelete` / 撤销中的 `NodeLog.updateLast(ctx, next)` 全部替换为：

```kotlin
scope.launch(Dispatchers.IO) {
    LearnRebuild.correct(ctx, recordId, next)
    withContext(Dispatchers.Main) { snack?.showSnackbar("已修正，学习样本已重算") }
}
```

- 修正来源由 `Src.BACKFILL` 改为 `Src.MANUAL`（绿色=手动），与文案「点按节点可改/删」一致；提示文案改为「点按节点可修正时间」以提升可发现性。
- 修正日期基准：`NodeTimeline` 增加可选 `dateBase: Long? = null`，`RecentRunCard` 传 `nodes.maxOf { it.at }`；确认时用 `atOn(minute, dateBase)`（新函数，逻辑同 `atToday` 但基准日期取 `dateBase`），避免修正历史记录时把时间写成今天。
- `LearnRebuild` 新增：

```kotlin
private val REPLAYABLE = listOf("node\u001f", "habit\u001f", "ride\u001f", "clock\u001f")

fun correct(ctx: Context, id: String, nodes: List<NodeLog.Stamp>): NodeLog.RunRecord? {
    val rec = NodeLog.record(ctx, id) ?: return null
    return applyCorrection(ctx, rec.copy(nodes = nodes))
}

fun applyCorrection(ctx: Context, rec: NodeLog.RunRecord): NodeLog.RunRecord? {
    // 测试/中途结束：只改记录，不制造学习样本
    if (rec.test || rec.aborted) {
        NodeLog.replace(ctx, rec); return rec
    }
    val replayable = rec.learned.filter { e -> REPLAYABLE.any { e.startsWith(it) } }
    if (replayable.isNotEmpty()) Learn.rollback(ctx, replayable)
    Learn.beginJournal()
    runCatching { replay(ctx, rec) }
    val fresh = Learn.endJournal()
    val updated = rec.copy(learned = rec.learned.filterNot { e -> REPLAYABLE.any { e.startsWith(it) } } + fresh)
    NodeLog.replace(ctx, updated)
    return updated
}
```

- `NodeLog` 新增 `replace(ctx, rec)`：按 `id` 替换后 `writeHistory`（同时自增 `revision`，首页立即刷新）。
- `replay()` 依赖 `Learn.recordNode/record/recordBoardClock` 的「同一天只留第一次」逻辑：先精确回滚旧样本，再按修正后的节点重写，不会污染其它行程。

### 问题 3：确认下车后不再响铃/震动

- `resetAlightGuard(keepAck: Boolean = false)`：`keepAck = true` 时不清 `alightAckedAt`（其余字段照常重置）。
- `markAlight(at, by, keepAck: Boolean = false)` 透传给 `resetAlightGuard`。
- `ackAlight()` 末段分支：
  - `legIdx >= trip.legs.size - 1` → `markAlight(now, "user", keepAck = true)`，并再兜底 `alightAckedAt = now; alightStage = NONE`；
  - 换乘分支保持 `markAlight(now, "user")` + `advanceLeg()`，下一段仍能正常提醒。
- `LiveNotifier.alert()` 的 `NotificationCompat.Builder` 增加 `.setOnlyAlertOnce(true)`：同一 id 的后续更新不再由通知渠道触发震动/提示音，真正的响铃仍由 `AlarmBuzzer.ring()` 控制，避免重复触发。
- 不改「我知道了」的静音逻辑（只静音当前阶段，不记时间）。

### 问题 4：首末站点视为到站打卡

**记录详情（`RecordsScreen.RecordDetail`）**

- `stationLegs` 分支里，先取该段的节点时间：
  `val boardAt = eff[NodeRef(Kind.BOARD, i)]?.at; val alightAt = eff[NodeRef(Kind.ALIGHT, i)]?.at`
- 渲染每一站时：
  - 有人工打卡 → 用打卡时间；
  - 否则 `idx == 0` 用 `boardAt`（确认上车），`idx == names.lastIndex` 用 `alightAt`（我已下车），其它站保持 `—`。
- 旧记录（无 `legStops`）保持现状。

**学习侧（`Learn` / `CommuteService.flushStopLearn`）**

- `Learn.recordStops()` 去掉 `if (list.isEmpty()) return`：允许只有首末两端（上车→下车）时，用 `atAlight` 补 `StopMark(hops, atAlight)`，`intervals()` 会产出 `span==hops` 的区间并入「每站平均」样本；`span==1` 时直接成为该区间样本。
- `flushStopLearn(at, implicitOk: Boolean = false)`：只有 `markAlight()` 调用时传 `implicitOk = true`（此时 `at` 就是下车时刻），`finish()` 的兜底调用保持要求有显式打卡，避免把下车后的步行时间算进乘车。
- 这样「确认上车 + 我已下车」虽没点站，也会进入算法学习；与问题 5 的线路排序共用同一份线序数据。

### 问题 5：地铁线路色 + 站间时长排序

**A. 彩色线路牌**

- 复用 `ui/LineBadge`、`ui.lineColor(c)`、`ui.lineColor(null, name)`、`ui.shortLine(name)`（`Transit.colorOf` 内部有缓存）。
- 行程详情 `RecordsScreen`「行程段」：把 `Text("${i+1}. ${leg.title()}")` 改为：

```kotlin
Row(verticalAlignment = Alignment.CenterVertically) {
    Text("${i + 1}.", 15.sp, Bold, ink)
    val metros = leg.candidates.filter { it.type == Candidate.Type.METRO }
    if (metros.isNotEmpty() && leg.isMetroOnly()) {

            if (k > 0) Text(" / ", 13.sp, dim)

            if (c.metroDir.isNotEmpty()) Text(" 往${c.metroDir}", 11.sp, dim)

```

- 算法学习 `LearnScreen`：
  - 「站间行车时长」卡片标题行：`LineBadge(shortLine(lineName), lineColor(null, lineName))` + `往${dir}`；
  - 「地铁班次偏差」：`${m.stop}` 前加 `LineBadge(shortLine(m.line), lineColor(null, m.line))`；
  - `MetricLine`：`LearnReport.Line` 增加 `badgeNames: List<String> = emptyList()`；有值时在标签前渲染 `LineBadge`，标签改为「乘地铁」（避免与线路名重复）。`LearnReport.build` 里对地铁段填 `candidates.filter{METRO}.map{name}.distinct()`。

**B. 站间时长按行车方向排序、列全、缺样本留空**

- 新增线序数据：`Learn` 增加 `private const val STOP_SEQ = "s|"`，`recordStops()` 每次把本次 `names` 与已存序列合并后写回 `s|<lineKey>`（`\u001f` 分隔）。
- `RideStops.kt` 新增纯函数（可单测）：

```kotlin
object StopOrder {
    /** 把多次乘车的站序 / 已知区间边合并成一条行车方向的站点序列 */
    fun merge(sequences: List<List<String>>): List<String>
}
```

  实现：建 `next: LinkedHashMap<String,String>`，`zipWithNext` 写入 `putIfAbsent`；没有前驱的站为起点依次走链，剩余（含环）按首次出现顺序补齐。

- 重写 `Learn.stopStats()`：
  - 解析 `a|`、`p|`、`s|` 三类键；
  - 每个 `lineKey`：`seq = StopOrder.merge(已存序列 + 每个区间边 listOf(from,to))`；
  - 输出 `pairs = seq.zipWithNext().map { (a,b) -> StopPair(a, b, pairMedian[a|b]) }`（`StopPair` 为新增 data class，`median` 可为 `null`）；
  - 线路集合 = `avgs.keys ∪ pairs.keys ∪ seqs.keys`，排序不变。
- `LearnReport`：
  - `StopBlock` 改为 `(lineName, dir, perHop, pairs: List<StopPair>)`，`lineKey` 用 `|` 拆成线路名与方向；
  - 删除 `.take(8)`；`pairs` 全部输出，`median == null` → `value = ""`（留空）。
- `LearnScreen`：区间行改为 `Text("${p.from} → ${p.to}")` + 右侧 `Text(p.value, TnumStyle)`；空值时右侧不显示文字（保留占位高度）。

**C. 原型（彩色线路牌）**

行程详情：

```text
行程段
1.  [4]  往世纪大道        人民广场 → 世纪大道
2.  [7]  往花木路          龙阳路 → 花木路
```

算法学习-站间行车时长：

```text

区间用时
人民广场 → 南京东路              88 秒
```

### 问题 6：点「我知道了」后有反馈且按钮隐藏

**A. 快照把静音状态传给界面**

- `LiveSnapshot`（`CommuteService.kt:33`）新增 `val alarmMuted: Boolean = false`。
- 主循环发布看板处（`CommuteService.kt:2017` 的 `LiveSnapshot(...)`）增加：
  `alarmMuted = st != AlightGuard.Stage.NONE && alarmMutedStage == st`。
- `muteAlarm()` 在 `fireAlight(...)` 之后立即补发一次：
  `LiveState.snapshot.value?.let { LiveState.publish(this, it.copy(alarmMuted = true), deadlineAt) }`，
  让按钮在点击的同一帧消失，不用等下一轮轮询。
- 阶段升级时 `fireAlight()` 已把 `alarmMutedStage = null`（`CommuteService.kt:813`），下一轮快照 `alarmMuted = false`，按钮自动重新出现，符合「阶段变化必须重新响」。

**B. 界面反馈**

- `LiveBoard` 按钮区（约 421–432 行）在 `s.alightDue` 时：
  - `s.alarmMuted == false` → 显示「我知道了」；
  - `s.alarmMuted == true` → **不显示该按钮**；
  - 「我已下车」始终显示。
- 按钮行下方增加一行提示（仅 `s.alightDue && s.alarmMuted`）：
  `Text("已静音本次提醒 · 下车前不再响", 11.sp, Color.White.copy(alpha = 0.45f))`。
- `DemoPlayer.frame()` 的 `snap()` 里补 `alarmMuted = muted?.first == leg`，演示回放行为一致。

### 问题 7：`alightDue` 时隐藏「到站打卡」

- `LiveBoard` 中把：
  `if (stopNames.size > 1) Pill("到站打卡", ...)`
  改为：
  `if (stopNames.size > 1 && !s.alightDue) Pill("到站打卡", ...)`。
- 语义：`stopNames` 本身不含上车站与下车站；当只剩本段下车站（`s.alightDue = true`）时，下车站的到站由「我已下车」记录 `ALIGHT` 节点完成（问题 4 又会把该时间显示为末站打卡、并进入学习），不再提供多余的站点打卡。
- 中间站（`s.alightDue = false`）仍保留「到站打卡」，用于校正后续到站时间。
- 「已打卡 N 站」摘要与撤销逻辑不变；演示回放同样受 `alightDue` 控制。

## 四、兼容与数据迁移

- 历史记录：不改动已有 JSON 字段；新增 `s|` 线序键只增不减。旧数据没有线序时，`StopOrder.merge` 用已学区间边还原顺序（仍能满足「按方向排序」），无法推断的缺口不显示。
- 旧版 `LAST` 单条记录：`lastRecord` 仍通过 `records()` 的迁移逻辑读取；修正时 `replace()` 会落成 HISTORY。
- `learned` 日志：修正走「先回滚、再重放」，记录里保存的是合并后的日志，后续删除记录仍可精确回滚。
- 修正入口只在最近行程；行程记录详情保持只读。
