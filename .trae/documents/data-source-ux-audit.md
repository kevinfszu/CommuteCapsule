# 数据源页面 UX 走查与改进方案

范围：「数据源」弹窗（SourceDialog）与「用高德生成数据源」弹窗（AmapImportDialog）。

## 结论

当前功能完整、路径可用，但**层级与反馈**是主要短板：删除操作无确认且与导入同权重、错误提示可能出现在视口外、导入结果只靠 Toast。本轮已修复 P0，其余按 P1/P2 排期。

严重度：P0 = 会造成数据丢失或"操作了但没反馈"；P1 = 明显增加认知负担/重复劳动；P2 = 打磨项。

## 一、信息架构

| 问题 | 影响 | 级别 | 处置 |
| --- | --- | --- | --- |
| 状态（当前数据源、实时到站）与操作（导入、生成、删除）混排在一个长列，删除与导入同形同权 | 用户扫一眼分不清"我在看什么"和"我能做什么"，危险操作易误触 | P0 | 已修：删除改为二次确认 + danger 样式，置于内容末尾 |
| 「区域编号」是内部概念，却夹在状态与操作之间 | 阻断"导入 → 看到结果"的主视线 | P1 | 降权：默认折叠为一行「区域编号 gz（修改）」，展开后才是输入框 |
| 已导入线路只有名称 | 无法确认"导入的是不是我要的那条线" | P0 | 已修：每行右侧显示站数；后续可再加方向数与更新时间 |
| 底部提示引用 `docs/DATA_SOURCE.md` | App 内用户无法访问该路径，属开发者语言 | P2 | 改为「线路文件格式见仓库文档」，或直接删除 |
| 无数据时只有两个按钮 | 新用户不知道"内置演示数据"从哪来、"为什么要导入" | P1 | 增加空状态说明：当前使用内置演示线路，导入后立即替换 |

## 二、用户流程

| 问题 | 影响 | 级别 | 处置 |
| --- | --- | --- | --- |
| 删除导入数据即时生效、不可撤销 | 误触即丢失全部导入线路 | P0 | 已修：行内二次确认 |
| 导入成功仅 Toast，弹窗内容不跳转 | 用户在长弹窗中看不到新增线路，误以为失败 | P0 | 已修：顶部持久成功条 + 列表就地更新 |
| 高德弹窗嵌套在数据源弹窗之上（双弹窗 + 双层遮罩） | 返回层级模糊，"取消"到底退到哪一层不明确 | P1 | 改为单弹窗内两级视图（列表页 ⇄ 生成页），标题随层级变化 |
| 生成成功后仅回到数据源弹窗 | 缺少"下一步"（去首页看该线路 / 继续添加另一条） | P2 | 成功条内提供「继续添加」与「完成」两个动作 |
| 查询中可关闭弹窗 | 协程被取消，无副作用，但用户会丢失已填内容 | P2 | 查询中允许关闭但保留上次输入（关键词持久化后自然缓解） |

## 三、操作效率

| 问题 | 影响 | 级别 | 处置 |
| --- | --- | --- | --- |
| 关键词每次打开都为空（Key、城市已记忆） | 反复调试同一条线要重输 | P1 | 关键词同样持久化；并提供最近 3 条查询的 chip |
| 剔除未开通车站只能逐站取消 | 线路长时操作成本高 | P1 | 站点区加「全选 / 全不选」，并显示「已剔除 N 站」 |
| 单站用时用两个自由输入框 | 小屏占一行、易输错 | P1 | 改为预设 chip（地铁 2:20 / 公交 1:30 / 自定义），保留自定义输入 |
| 查询中/生成中输入框仍可编辑 | 参数与结果可能不一致（改了 Key 但结果还是旧的） | P1 | GlassField 增加 `enabled`，请求期间整体禁用 |
| 无 Key 时字段全空、只有一段说明 | 新用户不知道去哪里申请，卡在第一屏 | P1 | 提供「去高德开放平台申请」可点击入口，并说明需创建 Web 服务 Key |

## 四、反馈机制

| 问题 | 影响 | 级别 | 处置 |
| --- | --- | --- | --- |
| 错误提示位于查询按钮下方 | 在底部点「生成并导入」校验失败时，错误在视口外，看起来像没反应 | P0 | 已修：错误条移到顶部并自动滚回顶部 |
| 请求只有按钮文案变化 | 网络慢时不确定是否卡死 | P1 | 查询按钮内加小型进度指示；请求中禁用全部输入 |
| 保留站点 < 2 时按钮仅变灰 | 不知道为什么不给点 | P0 | 已修：已选数旁直接提示「至少保留 2 站」 |
| 导入/生成 Toast 一个报总量、一个报增量 | 同一件事两种口径 | P2 | 统一为「本次导入 N 条，当前共 M 条」 |

## 五、视觉层级

| 问题 | 影响 | 级别 | 处置 |
| --- | --- | --- | --- |
| 数据源弹窗底部 4 个同形胶囊按钮 | 无主次，危险操作不醒目 | P0 | 已修：删除降为文字按钮 + danger |
| 高德弹窗单列过长（说明、三输入、结果、站点 190dp、用时、首末班、脚注） | 进入后看不到关键操作，滚动疲劳 | P1 | 按"输入 → 选线 → 校站 → 参数"分组，用分隔与小标题形成节奏；确认按钮固定在弹窗底部（已有） |
| 方向结果选中态只有浅底 + 粗体 | 选中感弱，与站点 Checkbox 语言不一致 | P0 | 已修：加 RadioButton |
| 12sp 灰字堆叠较多 | 层级只有 12/14/15 三档，说明性文字抢注意力 | P2 | 精简为一条主说明 + 其余放进 supportingText / 折叠说明 |
| 线路列表内层再滚动（168dp） | 小屏出现"弹窗滚动里套列表滚动"，手势易误判 | P1 | 去掉内层滚动，随主内容滚动；数量多时再启用 |

## 六、组件一致性

| 问题 | 影响 | 级别 | 处置 |
| --- | --- | --- | --- |
| 文案混用 API / JSON / adcode / 文档路径 | 与设置页、首页口语化风格不一致 | P2 | 统一为用户语言，技术细节放 supportingText |
| 危险操作样式与其他页面不一致 | 用户对"红色 = 不可逆"的预期落空 | P0 | 已修：DialogButton(danger = true) |
| 列表行圆角 12/14、间距 6/10 混用 | 细节松散 | P2 | 统一为 14dp 圆角、8dp 间距，抽一个本地行组件 |
| 嵌套 AlertDialog | 系统层面两个弹窗叠加，返回键行为不统一 | P1 | 见「用户流程」：改为单弹窗两级视图 |

## 本轮已实施（P0）

1. 删除导入数据：二次确认 + danger 样式，明确后果文案。
2. 导入成功：顶部持久成功条，列表就地刷新。
3. 已导入线路：显示每线站数（正反方向合并取较大值）。
4. 高德弹窗：错误条移至顶部并自动滚回可见区域；所有校验与网络错误统一走该入口。
5. 方向选择：改用 RadioButton，与站点勾选语言一致。
6. 站点不足：直接提示「至少保留 2 站」。
7. 结果过多：选中方向后折叠结果列表，只保留选中项并提供「换一条」（实测关键字「13」会返回 13 条结果，此前选完还要滚过整张列表才能到站点与参数）。

## 后续执行建议（按顺序）

1. **P1 单弹窗两级视图**：把 AmapImportDialog 从 `AlertDialog` 改为内嵌内容页，SourceDialog 用 `page` 状态控制标题与返回；消除双遮罩与返回歧义。
2. **P1 选中后收起输入区**：选定方向后把「Key / 城市 / 关键字 / 查询」折叠为一行摘要（如「广州 · 13 · 重新查询」），让「选中方向 + 站点列表 + 参数」尽量一屏可见；折叠后列表的滚动位置也应回到选中行，避免当前行被裁在视口边缘。
2. **P1 输入持久化与预设**：关键词记忆 + 最近查询 chip；单站用时预设 chip；站点全选/全不选。
3. **P1 请求期禁用**：`GlassField` 增加 `enabled` 参数，查询/生成期间禁用输入与二次操作。
4. **P1 区域编号降权 + 空状态引导**：折叠为一行，必要时展开；无 Key 时给出申请入口。
5. **P2 文案与视觉收口**：Toast 口径统一、去技术词、行组件统一圆角间距、内层滚动移除。

## 验收标准

- 删除必须两步，且删除后列表与「当前源」立即回到默认。
- 任何校验失败后，错误文案必须出现在可视区域内（自动滚到顶部）。
- 导入成功后不依赖 Toast 也能确认结果（顶部成功条 + 列表新条目 + 站数）。
- 站点不足 2 个时，原因在按钮附近可见。
- 深浅色下错误条、成功条对比度均达到可读（AA 目标）。
