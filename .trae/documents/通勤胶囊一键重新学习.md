# 通勤胶囊：算法学习「一键重新学习」

## 概要

在「算法学习」页右上角加「重新学习」入口：确认后，按现有历史行程记录重新计算可推导的学习数据，让新的学习规则即时作用到历史数据上，不用再跑一个月。

- **重建**：节间时长（进站→上车、下车→出站、换乘、行程段时长、下车→到达、全程）、上车时刻（始发站/换乘站）、每段乘车时长、上车习惯。
- **保留**：站间打卡、地铁基站、公交速度、步行样本、提醒→确认下车（历史记录里没有原始数据，无法重建）。
- **范围**：只使用当前历史记录（最多 30 条、30 天）；更早的旧样本随重建清除。
- 重建后把每条记录的学习日志一并更新，以后删除记录仍能精确回滚。

## 现状分析

- 历史记录：[NodeLog.RunRecord](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/NodeLog.kt#L212-L254) 已保存 `trip.toJson()`、`nodes`（节点时间戳）、`aborted/test`、`learned`（该次写入的学习样本日志），[records()](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/NodeLog.kt#L270-L284) 最多返回 30 条、30 天内。**数据足够重算可推导项**，但 `joinLeg`、提醒时刻（`alightAlertAt`）、GPS/基站原始数据没有存，所以换乘部分/REACT/基站/速度/站间无法重算。
- 学习写入：[Learn.recordNode](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/Learn.kt#L287-L297) **用 `LocalDate.now()` 作为样本日期**；直接重放历史会把所有样本记成今天并因「同一天只留一条」互相覆盖，必须支持传入样本时间。
- 当前学习逻辑：[CommuteService.learnNodes()](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/CommuteService.kt#L868-L925)，在服务里依赖运行时状态（`joinLeg`、`alightAlertAt`、`restored/manualRun`）。重学需要一份不依赖服务实例的等价实现。
- 删除记录回滚：[Learn.rollback](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/Learn.kt#L38-L52)，按 `learned` 里的 `node/clock/ride/habit` 日志精确撤销，所以重建后必须把每条的 `learned` 改写为新日志。
- 页面：[LearnScreen.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/LearnScreen.kt#L35-L48)，`report` 目前是 `remember { LearnReport.build(ctx) }`，重学后需要能刷新。
- 页头按钮：`GlassPage` 支持 `actions`，`PillButton` 已是现成样式（见 [GlassKit.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/GlassKit.kt#L85-L175)）。

    Metric.WAIT, Metric.TRANSFER, Metric.EXIT_WALK, Metric.LAST_WALK, Metric.LEG_SPAN, Metric.TRIP,

fun clearForRebuild(ctx: Context, tripIds: Collection<String>) {
    val np = ctx.getSharedPreferences(NODES, Context.MODE_PRIVATE)
    np.all.keys.filter { k -> REBUILDABLE.any { k.startsWith("${it.name}:") } }
        .forEach { np.edit().remove(it).apply() }
    ctx.getSharedPreferences(BOARD_CLOCK, Context.MODE_PRIVATE).edit().clear().apply()
    ctx.getSharedPreferences(RIDE, Context.MODE_PRIVATE).edit().clear().apply()
    val lp = ctx.getSharedPreferences(PREFS, Context.MODE_PRIVATE)
    tripIds.forEach { lp.edit().remove(key(it)).apply() }
}

## 假设与决策

- 只重建**可从历史记录推导**的数据（用户选择）；站间打卡、基站、公交速度、步行、REACT 保留，不提供「全部清空」。
- 只使用现有历史范围（30 条 / 30 天），更早的样本被清除，不做「追加」以免同日重复拉偏中位数（用户选择）。
- 历史记录没有 `joinLeg`（半路上车）信息，重放按完整段处理；这类记录可能产生略偏小的行程段样本，属于可接受误差。
- 提醒→确认下车（REACT）无法重算，原样保留。
- 重建在 IO 线程执行，最多 30 条记录，耗时可忽略；完成后立即刷新报表。
- 重建不发生网络请求，不改动行程定义与时间窗（上车习惯样本变了，下次自动调整窗口时自然生效）。
