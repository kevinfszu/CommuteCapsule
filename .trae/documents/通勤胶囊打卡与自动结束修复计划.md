# 通勤胶囊：站点打卡、双击防误触、等车信息与防误结束

## Summary

本轮修复 6 条问题，全部集中在看板与服务状态机，不改线路数据、不新增高德选点：

1. 打卡弹窗站点列表被「双重排除下车站」少算一站，导致 11 号线选不到「华景路」、13 号线选不到「沙村」；保持「当前站前后 5 站」窗口，只修正上限。
2. 车辆启动（过站/进站变化）后仍显示「撤销上车」，改为自动收起；无定位可判启动时，30 秒后也自动消失。
3. 节点时间轴由单击改为双击：双击空白节点记「现在」，双击已记录节点撤销；长按改时间保留。
4. 等车阶段（出发后上车前、换乘下车后上车前）在乘车看板显示「下一班到站时刻 · 当前发车间隔」。
5. 地铁末段还在车上时，掉地下基站被误判为「出站/已到站」并结束行程；改为出闸前绝不自动结束。
6. 打卡列表上限算错导致终点前的最后一站被隐藏，修正后仍为「当前站前后 5 站」（限本段内）。

明确不做：新建行程时的高德地图出发地/目的地选点（用户确认本轮只修防误结束）；不改公交/班车结束规则；不引入「手动输入站名」。

## Current State Analysis

### 1、6 打卡站点列表缺站（已定位，非数据缺失）

`LiveBoard.kt` 打卡弹窗（`if (pickStop && stopNames.size > 2)` 一段）：

```kotlin
val maxIdx = stopNames.size - 2
val here = (listOfNotNull(s.stopsPassed, markIdx).maxOrNull() ?: 0).coerceIn(0, maxIdx)
val from = (here - 5).coerceAtLeast(1)
val to = (here + 5).coerceAtMost(maxIdx)
val rows = (from..to).toList()
```

而服务端 `CommuteService.publishStops()` 已经做过一次排除：

```kotlin
val names = stopNamesOf(legIdx)          // 含上车站与下车站
stopChoices.value = names.dropLast(1)    // 已排除下车站
```

即 `stopNames`（界面拿到的 `CommuteService.stopChoices`）**已不含下车站**，弹窗再按 `size - 2` 计算，等于把最后一个「中间站」也隐藏了：

* 11 号线：`names = [华师, 华景路, 天河公园]` → `stopChoices = [华师, 华景路]` → `maxIdx = 0`，只能选「华师」（截图 1）。
* 13 号线：`stopChoices = [鱼珠, 裕丰围, 双岗, 南海神庙, 夏园, 南岗, 沙村]` → `maxIdx = 5`，列表到「南岗」为止，「沙村」被隐藏（截图 2）。

另外弹窗入口条件是 `stopNames.size > 2`：只有「上车站 + 1 个中间站」的线路（如 11 号线）**根本打不开弹窗**。

`CommuteService.markStop(idx)` 的校验是 `idx in 0 until names.size - 1`（`names` 含下车站），与界面列表 `lastIndex` 一致，服务端不会拦截，因此只需修界面。

### 2 撤销上车按钮

`LiveBoard.kt` 按钮区 `canUndo = undoAt > now`；`undoUntil` 只在三种情况清除：重置（L337）、`undoBoard()`（L968）、自动上车时 `boardSnap != null` 的分支（L1096）。人工上车后 `riding = true`，车辆启动不会清 `undoUntil`，按钮会一直留满 `UNDO_MS`（当前 2 分钟）。

车辆启动的现成信号：

* 地铁：`rideTick` 里 `metroAnchorIdx = k`（L1732，按定位认定列车已过第 k 站）。
* 公交：`rideTick` 里 `busSeg = sn.seg`（L1747，沿线投影进入下一段）。

### 3 节点误触

`NodeTimeline`（`LiveBoard.kt`）当前用 `detectTapGestures(onTap = …)`：

* `tapOpens = false`（看板）：单击当前节点 `stampCurrentNode()`，单击其它节点 `undoNodeIfFresh(ref)`（仅 5 秒内可撤销）。
* 单击即写时间，容易误触。

用户已确认：改「节点时间轴」，打卡站点列表保持单击。

### 4 等车信息

`LiveSnapshot` 目前没有「下一班到站 / 发车间隔」字段。但等待分支（`tick()` 非 riding，L1383-1389）已具备全部原料：

* `a.arrival?.etaSec`：下一班车还有多少秒到本站（地铁由 `Decision.metroSchedule` 推算，公交由实时数据）。
* `tt?.atMs`：`BusTimetable.predict` 给出的「近 N 天常见到站时刻」，仅在实时无车时使用。
* `a.option?.candidate`：可用 `Decision.headwayAt(分钟, weekday, bands)`（地铁）或 `Candidate.headwaySec(分钟, weekend)`（公交）算当前时段间隔。
* `secOfDay`（L1323）、`weekday` 在等待分支内可取得。
* 倒推出发的 `planTick`（L1554）属于「还没出发」，不填这两项。

### 5 地铁末段过早结束（已定位）

`CommuteService.onCellEdge` 的 `MetroGate.Edge.EXIT`（L2833-2847）：

```kotlin
riding && cur.isMetroOnly() && legIdx == last -> {
    endMetroRide()
    stampNode(NodeLog.Kind.EXIT, legIdx, edge.second, NodeLog.Src.AUTO)
    markAlight(edge.second, by = "cell")
    Diag.mark(this, "离开地铁里的基站，判断已出站，行程结束")
    arrived = true
    endTrip("cell_exit")      // 还在车上（高架/地面区间掉地下基站）就直接结束
    return
}
```

13 号线南岗—沙村—白江为地面/高架区间，列车行驶中离开地下基站即触发该分支：补记「下车/出站」并 `endTrip`，通知显示「已到站」，与截图 3、4 完全吻合。

现有其他结束路径：

* `tap_exit`（刷闸通知，L2575）：可信，保留。
* `ackAlight`（人工「我已下车」，L710-718）：地铁末段只记下车、不结束，已有正确注释。
* `placeFix` H3（家/公司围栏 + 3 分钟，L2091-2109）：有 `metroStillInside()` 守卫。
* `rideTick` 到站（L1840-1844）：地铁末段只 `markAlight`，不结束。

因此过早结束的唯一来源就是 `cell_exit`。

用户已确认：**刷闸出站才结束**；未出闸门前一律不自动结束。

同第 1 条：`maxIdx` 把最后一个中间站（沙村）错误排除在窗口上限之外，站在沙村时窗口也到不了它。

## Assumptions & Decisions

1. 「节点」= 看板上的节点时间轴（用户已确认）；到站打卡站点列表维持单击。
2. 双击撤销仍沿用 `undoNodeIfFresh` 的 5 秒窗口与 MANUAL/BACKFILL 限制；自动写入的节点不可撤销。
3. 「车辆启动」以 `metroAnchorIdx` 前进、`busSeg` 前进为准；无定位可判启动时，撤销按钮在 30 秒后自动消失。
4. 等车信息只在服务端等待 tick 发布，`planTick`（还没出发）不显示；`showWaitInfo` 额外过滤「刚开行程仍在起点」的情况。
5. 发车间隔：地铁用分时段表；公交仅在存在真实分时段数据（`weekdayBands`/`weekendBands`）时显示，避免把合成值当真实间隔。
6. 地铁末段自动结束只认刷闸（`tap_exit`）与目的地围栏（`placeFix`）；刷闸前行程可能多跑一会儿，由 `deadlineAt` 兜底，不会再出现「未出站已到站」。
7. 高德地图起终点选点、手动输入站名：本轮不做。
