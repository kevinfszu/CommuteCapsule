# 地铁行程节点时间轴与防坐过站方案

## 1. 摘要与已确认决策

把一趟通勤拆成可记录的节点时间轴：**出发 → 进站 → 上车 → 下车 →（换乘重复）→ 出站 → 到达**。关键节点（进站、下车、出站）由手机刷卡通知与多信号自动判定；非关键节点（出发、上车、下车终点、到达）采用「时间轴打点」，点一下记当前时间，长按补录，缺失不阻塞后续节点。

已确认的三项决策：

1. **非关键节点交互**：时间轴打点。通知卡片与首页常驻一行节点，点一下记「现在」，长按改时间；缺失不追问、不阻塞下一个节点，行程结束后可补录。
2. **防坐过站**：多信号到站判定（到站播报、定位锚点、基站 E1 模型 + 磁场停车特征）；换乘站与**终点站**同等处理；到站前除震动外增加**响铃**，直到用户确认「我已下车」。
3. **学习范围**：只做时长与校准（各节点耗时、换乘步行、乘车时长、提醒响应延迟），不做通勤画像、风险评分或趣味统计。

## 3. 节点模型

### 3.1 节点定义

| 节点          | 作用域 | 时间来源优先级                    | 关键性    |
| ----------- | --- | -------------------------- | ------ |
| 出发 `DEPART` | 整趟  | 人工打卡 > 自动启动时刻（离开出发地/时间窗）   | 非关键    |
| 进站 `ENTER`  | 地铁段 | 刷卡通知「已进站 / 行程中」 > 基站/定位推断  | **关键** |
| 上车 `BOARD`  | 每段  | 人工打卡 > 刷卡上车（公交）> 自动判定      | 非关键    |
| 下车 `ALIGHT` | 每段  | 人工「我已下车」 > 刷卡出站 > 播报/定位/时间 | **关键** |
| 出站 `EXIT`   | 地铁段 | 刷卡通知「刷卡完成/已出站」 > 自动推断      | **关键** |
| 到达 `ARRIVE` | 整趟  | 人工打卡 > 尾段驻留定位              | 非关键    |

每段可有多个候选交通方式（`Leg.candidates`），因此节点按 `(kind, leg)` 唯一，不按线路唯一；实际乘坐的线路记录在节点备注里。

### 3.2 缺失时的补算规则

补算只发生在**行程结束结算**时，且标记为「推算」：

* `BOARD`（地铁段）缺失：`ENTER + n`，`n` 由用户预估，默认 180 秒。
* `BOARD`（公交段）缺失：用手机刷卡上车时刻；没有刷卡则 `ALIGHT - 该段实测中位数`。
* `BOARD`（转乘段）缺失：`上一段 ALIGHT + 换乘步行中位数`（不足 3 个样本时用 `Leg.transferWalkMin`）。
* `ALIGHT`（转乘）缺失：`下一段 BOARD - 换乘步行中位数`；仍无锚点则用本段预计到站时刻。
* `ALIGHT`（终点）缺失：`EXIT - n`，`n` 由用户预估，默认 120 秒。
* `ARRIVE` 缺失：`EXIT/ALIGHT + 末段步行中位数`；尾段驻留成功时直接用定位到达时刻。
* 用户提前「结束行程」：只补算已有锚点的节点，之后未发生的节点保持缺失，不臆造。

`n` 放在行程级配置（`Trip.boardEstimateSec`、`Trip.alightEstimateSec`），编辑页高级项可改；不同换乘站结构差异很大，不做全局值。

## 4. 交互方案：时间轴打点

### 4.1 展示位置

1. **首页实时看板**（[LiveBoard.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/LiveBoard.kt)）：在顶部线路牌与大字倒计时之间插入一行可横向滚动的节点条。当前节点居中，前后节点半透明。
2. **行程结束后的「最近行程」卡片**（[HomeScreen.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/HomeScreen.kt) 行程列表上方）：显示最近一趟的完整时间轴，用于补录与核对。
3. **通知栏**：标准通知无法放时间轴，只提供**一个动态动作**，文案随状态变化：「记：上车」「记：下车」「记：到达」「我已下车」。完整时间轴在 App 内。这是 Android 通知能力的硬限制，不强行模拟。

### 4.2 节点条状态

| 状态 | 视觉         | 含义         |
| -- | ---------- | ---------- |
| 实测 | 实心、完整不透明   | 人工打卡       |
| 刷卡 | 实心、带卡片图标   | 手机刷卡通知     |
| 自动 | 实心、略低不透明   | 定位/播报/算法判定 |
| 推算 | 虚线框、`≈` 前缀 | 结束时补算      |
| 补录 | 实心、斜纹角标    | 用户在结束页改过   |
| 当前 | 黄色描边、轻微呼吸  | 下一个建议打点的节点 |
| 未到 | 灰色         | 还没到该节点     |

时间统一显示 `HH:MM`；长按弹出已有的 [Wheel.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/ui/Wheel.kt) 时间滚轮，按 1 分钟微调。

### 4.3 点击、长按与撤销

* **点当前节点**：立刻记 `MANUAL / now`，无需确认，不弹窗。
* **点已记录节点（5 秒内再次点）**：撤销该次人工打点，回到上一状态（防误触，沿用现有「撤销上车」2 分钟窗口的思路，缩短为 5 秒以免误撤真实记录）。
* **长按任意节点**：打开时间滚轮补录/修正，来源记为「补录」。
* **点未来节点**：不响应，避免把「现在」错误写到未来节点。
* **点过去的空节点**：不直接打「现在」，只提示长按补录。

### 4.4 不阻塞的保证

* 节点之间没有先后校验：忘记「上车」后仍可直接点「下车」，系统在结算时把「上车」标成推算。
* 不弹出「请先完成上一节点」之类拦截；打点失败/缺失不改变行程状态机。
* 同一节点重复打点只保留最后一次人工值；原有自动值作为对照写入行程记录，便于回溯。
* 用户补录后，依赖该节点的推算值**重新计算**；补录值不进入学习样本。

### 4.5 分场景

* **出发**：自动启动即记 `DEPART`；用户若在 App 里手动开始，记为人工。之后在首页节点条上仍可长按修正。
* **上车（始发/转乘）**：等车时当前节点为「上车」，通知动作显示「记：上车」；已上车但用户没点，10 分钟后不追问，`onBoarded` 自动值照常记录。
* **下车（转乘）**：不做静默节点，走第 5 节的强制确认流程；用户点通知「我已下车」或在节点条点「下车」，都记 `MANUAL`。
* **到达**：终点站下车后，节点条当前项自动切到「到达」；用户在走到公司/家后点一下即可。若尾段驻留定位先判定到达，则自动记录，用户无需操作。

## 5. 防坐过站（换乘站与终点站同级）

### 5.1 多信号到站判定

| 信号       | 来源                                               | 时延        | 可信度 | 用法                                           |
| -------- | ------------------------------------------------ | --------- | --- | -------------------------------------------- |
| 到站播报文本   | 系统出行胶囊 / 地铁 App 通知（`TransitNotif`、`TransitA11y`） | 秒级        | 高   | 直接给出「下一站/当前站」站名，映射到 `MetroRoute.stations` 下标 |
| 定位锚点     | 站厅/地上 GPS，`metroAnchorIdx`                       | 30 秒–2 分钟 | 中高  | 匹配 400 米内站点，锁定已过站数                           |
| 基站 E1 模型 | `MetroCells` 指纹与剩余时间                             | 30 秒      | 中   | 无播报时的主推算                                     |
| 磁场停车特征   | `TraceLog.magStopTick` 的 `mag_stop`              | 25–40 秒   | 中低  | 只作「至少又停了一站」的下界，向前修正不超过 1 站/2 分钟              |

融合规则（纯函数，便于单测）：

```text
currentIdx = max(播报换算下标, 定位锚点下标, E1 推算下标, 磁场下界)
currentIdx 每 90 秒最多前进 1 站，防止跳变
监听播报：
  「下一站 X」     -> currentIdx = index(X) - 1
  「X 到了 / 即将到达 X」 -> currentIdx = index(X)
目标下标 = alight 站（换乘站取下一段首站，终点站取最后一段下车站）
remaining = 目标下标 - currentIdx
```

播报文本优先于纯时间推算；播报与 E1 冲突时取播报，并立即用播报时刻校准 `arriveAnchorAt`。

### 5.2 分级提醒与响铃

| 阶段  | 触发                           | 通知                             | 声音       | 震动       | 重复                 |
| --- | ---------------------------- | ------------------------------ | -------- | -------- | ------------------ |
| T-2 | `remaining == 2`             | 胶囊更新「还有 2 站 · 准备下车」            | 无        | 短震一次     | 一次                 |
| T-1 | `remaining == 1` 或预计到站前 90 秒 | 1005「下一站下车「X」/ 请准备下车」          | 1 声提示音   | 两短一长     | 每 30 秒，直到到站或确认     |
| 到站  | 播报/信号判定 `remaining == 0`     | 1005「现在下车「X」/ 请立即下车」+ 动作「我已下车」 | 响铃 3–5 秒 | 强震动      | 每 15 秒，最多 6 次，直到确认 |
| 过站  | 已离开目标站且未确认                   | 1007「「X」已过站 / 请下车返回」           | 长响铃一次    | 强震动      | 每 20 秒，最多 3 次      |
| 终点站 | 同上，但 `remaining` 以终点站为 0     | 与换乘站完全一致                       | 与换乘站完全一致 | 与换乘站完全一致 | 与换乘站完全一致           |

响铃实现：新增 `AlarmBuzzer`，用 `Ringtone`/`MediaPlayer` 在 `STREAM_ALARM` 上播放 3–5 秒，`AudioAttributes.USAGE_ALARM`，短暂申请音频焦点；不使用通知渠道声音，避免渠道被用户改成静音后失效。震动继续走现有 `Vibrator`。不新增权限。

**戴耳机/睡着**：闹钟流在多数机型上会走耳机或扬声器，且勿扰默认允许闹钟；但系统音量、勿扰与耳机降噪无法由 App 保证。首页权限说明中明确提示「为保证响铃有效，请允许本应用打扰、保持闹钟音量」。

### 5.3 确认与停止

* 「我已下车」是唯一的确认动作：通知动作、看板节点条、锁屏动作都可触发。
* 确认后：`ackAlight = true`、`AlarmBuzzer.stop()`、停止该段所有重复提醒，并记 `ALIGHT = now / MANUAL`。
* 换段/结束/用户主动结束时统一停止响铃，防止下一段误响。
* 若用户在 T-1 就点「我已下车」，视为提前确认，不再等到站提醒。

### 5.4 误报抑制

* 新鲜且精度 ≤ 200 米的定位显示离下车站 1.5 公里以上时，不进入响铃阶段（沿用 `freshFar` 思路）；地下定位不满足该条件时不抑制。
* 没有任何播报、也没有可靠到站时间（`Learn.Ride.Source.DEFAULT`）时，只保留 T-2 胶囊提示，不升级响铃。
* 同一次到站只确认一次：以 `(leg, currentIdx)` 去重；确认后过站不再响。
* 响铃上限：到站阶段最多 6 次，过站最多 3 次，之后只保留通知，避免持续骚扰。

## 6. 数据学习（时长与校准）

### 6.1 派生指标

| 节点对         | 指标     | 用途                 | 最少样本 | 异常值约束    |
| ----------- | ------ | ------------------ | ---- | -------- |
| 出发 → 进站/上车  | 首段步行时长 | 出发建议、首页倒计时         | 3    | 1–40 分钟  |
| 进站 → 上车     | 闸机→站台步行 + 候车 | 地铁等车默认值（替换固定 3 分钟） | 5    | 0–20 分钟  |
| 上车 → 下车     | 本段乘车时长 | ETA、到站提醒、出发建议      | 3    | 2–180 分钟 |
| 下车 → 下一段上车  | 换乘步行时长 | 换乘倒计时、下一段赶车提醒      | 3    | 0–20 分钟  |
| 下车 → 出站     | 站台→闸机步行 | 出站后到达预估            | 5    | 0–15 分钟  |
| 出站 → 到达     | 末段步行时长 | 到达预估、出发建议          | 3    | 1–40 分钟  |
| 首次提醒 → 确认下车 | 个人反应时长 | 决定 T-1/T-2 提前量     | 3    | 10–300 秒 |

统计方式沿用现有做法：中位数、按行程/方向分开、样本按天去重；新样本不覆盖用户手填值。

### 6.2 使用规则

* `补录` 不进入学习样本。`推算` 只用于两个「固定差」指标，因为即使有推算误差也足够稳定：
  * 进站→上车（候车）：进站是刷卡实测，上车按预设推算，差值即候车时长；
  * 下车→出站（站内步行）：出站是刷卡实测，下车按预设倒推，差值即站内步行。
  其余指标（乘车、换乘步行、末段步行、反应时长、出发/到达）只认实测，避免推算自我强化。
* 手动的测试行程（`manualRun`）不学习；中途加入（`joinLeg >= 0`）不学习出发时间，与现有规则一致。
* 学习结果只影响**默认估算与提醒时机**；**绝不自动改用户设置的时间窗**（保留现有硬规则）。
* 换乘步行与站内步行按「站点名」聚合；乘车时长按「行程 + 段」聚合；反应时长按「行程 + 段」聚合。
* 当某指标样本不足时，回退现有逻辑：`Learn.ride`（实测 > 手填 > 站数估算 > 兜底）、`Leg.transferWalkMin`、固定地铁等车 3 分钟。

### 6.3 明确不学习的内容

* 不做通勤画像、过站风险评分、迟到概率、月度/年度趣味统计（本次范围外，后续可基于同一份节点数据再加）。
* 不根据节点时间自动调整时间窗（`Learn.autoAdjust` 不接入）。
* 原始定位轨迹仍只保留 30 天、仅本机，且不用于新的模型训练；节点数据只保留最近 7 天供「最近行程」补录。
* 不上传任何行程或节点数据。

## 7. 岭南通通知识别扩展

## 8. 数据结构与持久化

新增 `NodeLog.kt`（纯逻辑 + 本机存取）：

```kotlin
enum class Kind { DEPART, ENTER, BOARD, ALIGHT, EXIT, ARRIVE }
enum class Src { AUTO, TAP, MANUAL, ESTIMATED, BACKFILL }

data class Stamp(val kind: Kind, val leg: Int, val at: Long, val src: Src)

object NodeLog {
    fun stamp(kind: Kind, leg: Int, at: Long, src: Src)
    fun list(tripId: String): List<Stamp>
    fun has(kind: Kind, leg: Int): Boolean
    /** 结束时按第 3.2 节补算；返回完整时间轴 */
    fun resolveMissing(trip: Trip, now: Long, anchors: Anchors): List<Stamp>
    fun saveLastRun(trip: Trip, nodes: List<Stamp>)
    fun lastRun(): Pair<Trip, List<Stamp>>?
    fun clearRun()
}
```

* 进行中的节点存 `SharedPreferences("run_nodes")`，键为 `tripId + 开始时刻`；进程被杀后随 `run_state` 一起恢复。
* 每次打点同时写一条 `TraceLog.event("node", "kind" to ..., "leg" to ..., "src" to ..., "at" to ...)`，导出记录天然包含节点。
* 结束时把解析后的时间轴写入「最近行程」（保留 7 天），并清理进行中记录。
* 不改变 `run_state` 的 `sv` 版本；旧存档没有节点时，看板节点条显示「—」，不影响现有逻辑。

## 10. 分阶段实施

4. 结束结算（`resolveMissing`）与 `TraceLog` 节点事件。

### 阶段 2：防坐过站

5. 单测：阶段切换、确认后停止、远距离抑制、终点站。

## 12. 假设与取舍

1. 「行程中」按地铁进站处理；「刷卡完成/交易金额」按 `TAP` 处理，由当前段解释为地铁出站或公交上车。若实际公交也出现「行程中」，在真机样本确认后按当前段类型再细分。
2. 通知里的 `HH:MM` 视为事件时间；与当前时间相差超过 10 分钟视为旧记录，避免通知栏残留被误认。
3. 原生通知无法承载时间轴，通知栏只保留一个动态动作；时间轴以 App 内为主。
4. 响铃依赖系统闹钟流，受音量/勿扰/耳机路由影响，App 不能 100% 保证唤醒；权限说明中明确提示。
5. 推算是为了「不丢数据」，不是为了让数据看起来完整：推算与补录都带明确标记；补录不进学习，推算只用于候车与站内步行两个固定差。
6. 本次不做趣味统计、过站风险评分与迟到概率；节点数据已足够支撑后续单独加。
7. 终点站与换乘站使用完全相同的提醒文案、响铃策略与确认动作，不因「终点站反正要下车」而降低强度。
