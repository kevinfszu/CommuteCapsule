# 行程详情新增「站点时间轴」（默认折叠，用学到的站间时长推算）

## Summary

行程详情目前只有「节点时间轴」（出发 / 进站 / 上车 / 下车 / 出站 / 到达），没有逐站时间。本次为每条行程记录保存每段线路的站名、线路键与打卡所属段，并在详情页新增「站点时间轴」卡片：**以本段真实打卡和上下车时刻为锚点，中间站用该线路学到的站间时长（区间样本 → 每站均值）推算**，没有样本时才按时间均摊；卡片默认折叠，点标题行展开。「节点时间轴」保持现状、不折叠。

学习样本在行程进行中已由打卡写入（`Learn.recordStops`），本页只读取、不重复写入，避免同一趟行程被双计。

| 问题 | 决定 |

| 「站点时间轴」指哪种 | 新增逐站时间轴（每站经过时刻），不是把现有节点时间轴改名 |
| 折叠方式 | 节点时间轴不用折叠；站点时间轴默认折叠，点整行展开 |
| 中间站时刻怎么来 | 优先用该线路学到的站间时长推算，打卡时刻为精确锚点；禁止只用「上车 → 下车」线性均摊（用户纠正） |

## Proposed Changes

### 1. [RideStops.kt](file:///e:/001-Program/CommuteCapsule/app/src/main/java/com/busnotice/commute/RideStops.kt) — 新增逐站时刻算法

```kotlin
enum class StationSource { BOARD, ALIGHT, MARK, LEARNED, EVEN, NONE }
data class StationTime(val name: String, val at: Long?, val source: StationSource, val sec: Int? = null)

/**
 * 逐站时刻：
 * - 锚点：上车站用上车时刻、下车站用下车时刻、点过打卡的站用打卡时刻；
 * - 两个锚点之间：优先用该线路学到的站间时长（pairSec 逐区间 → perHopSec 每站均值）按比例分配真实时间；
 *   完全没有样本才按站数均摊（EVEN）；
 * - 锚点之外：沿用站间样本向前 / 向后外推；
 * - 任何来源都没有时为 NONE。
 */
fun stationTimes(
    names: List<String>,
    marks: List<StopMark>,
    boardAt: Long?,
    alightAt: Long?,
    perHopSec: Int?,
    pairSec: Map<String, Int>,
): List<StationTime>
```

规则（决定完备）：
- `names.size < 2` 返回空；越界打卡忽略；时间戳 `<= 0` 视为缺失。
- 第 0 站优先 `boardAt`（BOARD），缺失时用该站打卡（MARK）；最后一站优先 `alightAt`（ALIGHT），缺失时用打卡。
- 中间站按 `marks` 定位明确定义为 MARK。
- 相邻锚点 `(a, ta) → (b, tb)`（`b > a`）：逐跳权重 `pairSec["${names[k]}|${names[k+1]}"] ?: perHopSec`。
  - 权重全部存在 → 按权重比例分配 `tb - ta`，中间站为 LEARNED；
  - 有缺失 → 按跳数均摊，中间站为 EVEN。
  - 最后一站严格等于 `tb`，避免累计误差。
- 第一个锚点之前 / 最后一个锚点之后：用 `pairSec` → `perHopSec` 逐跳外推（LEARNED）；都没有则 NONE。
- `sec` 字段给出该站相对上一站的秒数（锚点站为实际差值），用于展开后的小字说明。

## Assumptions & Decisions

1. 中间站时刻是**基于学习样本的推算**，不是实测；只有打卡站与上下车节点是真实时刻，界面必须区分标注。
2. 学习写回已在行程进行中完成（`Learn.recordStops`），本页只读，避免同一段被重复计入样本。
3. 历史记录没有站名与学习键，无法可靠补全，因此只对改动之后的新记录显示该卡片。
4. 多段行程里公交只有保存时的当前段能拿到站名；拿不到的段跳过，不显示空段。
5. 折叠状态只在当前详情页内保存，默认折叠，不跨记录记忆。
6. 不修改节点时间轴与实时预测逻辑；实时预测本来就在用打卡修正后续站。
